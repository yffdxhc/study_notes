## 批次 5（2026-10-28）：从「分层」改为「回溯」——修正批次 4 的定性错误

**背景**：进一步澄清了关键定性——
**公司做的不是"某层新增"，而是"对 AOSP 某流程的客制化"，离不开 AOSP 底层逻辑。**

批次 4 用「厂商桌面新增 / AOSP 无此 flag」来描述 `canDoFastAnimation`，
**这个说法把线索扔了**：读者会以为"它不是 AOSP 的，所以和 AOSP 无关"，
恰好吃掉它最大的价值——**它指向 AOSP 的「App 启动动画决策」这个环节**。

### 修正

| 批次 4 的说法 | 批次 5 改为 |
|---|---|
| 「关键词属于哪一层」（AOSP / 厂商新增） | 「关键词**挂在 AOSP 哪个环节**」 |
| 「AOSP 无此 flag，对应能力在…」 | 「**客制化在 AOSP 的「启动动画决策」环节加了一条分支**」 |
| 结论「只有一行不是 AOSP」 | 结论「**10 个关键词全能挂到 AOSP 环节上；闪屏 = 100% AOSP 骨架 + 1 条客制化分支**」 |

### 方法论升级：关键词分层法 → **关键词回溯法**

```
旧：拆关键词 → 判断是不是 AOSP 的 → 是就查，不是就记位置
新：拆关键词 → 它挂在 AOSP 哪个环节 → AOSP 那里怎么走 → 客制化改了什么
```

| 只答「是/不是」 | 答「挂在哪一环」 |
|---|---|
| 得到一句话 | 得到「AOSP 本来怎么走 + 客制化改成什么」 |
| 线索用完就废 | 线索变成 AOSP 知识节点 |

### 改动清单

- 2.2：表格列改为「关键词 / 挂在 AOSP 哪个环节 / AOSP 标准实现 / 客制化」
- 2.2：读法流程改为三步回溯
- 6.1：速查表列改为「挂在 AOSP 哪个环节」，10 行全部补上环节归属
- 6.1：结论改写为「100% AOSP 骨架 + 1 条客制化分支」
- 自检清单：新增一条「能把陌生关键词回溯到 AOSP 环节」
- 导读 9.1：脱敏规则改为「关键词挂在哪个环节」可写
- 导读 9.3 → 9.2：**关键词回溯法**（替换原分层法），并修正章节编号顺序
- 导读 9.3：三段式第 ③ 段改名「客制化改在哪」

### 待核实不变
