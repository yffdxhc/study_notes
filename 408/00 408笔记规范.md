## 3. 命名规范

### 3.1 笔记文件

```
NN 主题名.md
 │    └── 中文主题，能一眼看出讲什么
 └────── 两位序号，按讲解顺序，从 01 开始
```

**规则：**

- **序号 + 一个空格 + 主题名**
- 序号**只用于排序**，不代表重要程度
- **不加"笔记""整理"等后缀**（章节文件夹已经说明它是笔记）
- 一份笔记 = **一个主题**（对应一讲，或一组紧邻的小讲）
- 主题名优先用**课程里的讲次标题**，可适当压缩变通顺

**反例 → 正例**

| 别这么写 | 这么写 |
|---|---|
| `第一章笔记.md` | `01 环境搭建与第一份C代码.md` |
| `笔记2.md` | `02 用调试器验证程序运行.md` |
| `内存.md` | `04 内存模型与进制转换.md` |

### 3.2 模块导读

模块根目录下固定叫 `00 {模块}模块导读.md`，`00` 表示"入口"。

例：`C语言/00 C语言模块导读.md`

### 3.3 章节速记（2026-11-07 新增）

每一章配一份 `C语言/速记/第N章 速记.md`——**把整章压成一页**。

> **位置：统一放在 `速记/` 目录，不散在各章文件夹里。**
> 好处：① 复习时一处翻遍全部；② 章节目录保持"只有笔记"的干净形态。
>
> **每个文件末尾必须有「对应笔记」表**，反向链回本章各篇。
> **每篇笔记的自检清单顶部，也要加一行链到本章速记。**

| | 笔记 `NN 主题.md` | 速记 `第N章 速记.md` |
|---|---|---|
| 作用 | **展开**：为什么、怎么推、反例 | **压缩**：结论清单 |
| 读法 | 第一次学 | 复习 / 考前 5 分钟 |
| 粒度 | 一讲一份 | **一章一份** |
| 长度 | 100~250 行 | **20~40 行** |
| 写法 | 表格 + 例子 + 自检 | **纯陈述句**，能一口气读完 |

**和「一句话记忆」的区别**：一句话记忆是**单篇 3 行**，速记是**整章 15~25 条**、交叉覆盖全章。

**写法要求**：

- 分 3~5 个小节（按知识块，不按讲次）
- **每条一句，能独立看懂**
- 易错点用 ⚠️ 标出，并写明"正确说法"
- 结尾给一个**掌握标志**（"能不看笔记做到 X"）
- 末尾附「对应笔记」表，点进去看展开

## 4. 每份笔记的固定结构

```markdown
# {序号} {主题}

> **逐字稿**：`C:\Users\18369\Documents\ZhuangFengYuan\408逐字稿\第N章\[序号]--NN_M_描述.doc`
> **视频**：网盘 `01.27考研王道【C语言入门课程】/0N.第N章/[序号]--NN_M_描述.mp4`
> 上一讲：{链接}｜下一讲：{链接}      ← 可省略，但同章内建议有
> **值得回看**：一句话点出老师现场演算 / 调试器操作 / 现场演示的位置
> ⚠️ **文稿口误**：（有则加）文稿把 X 识别成 Y，搜的时候用 Y

---

## 这一讲讲什么
（1~3 句，先给结论）

## 正文
（按知识点分节，多用表格、代码块、对照）

## 自检清单
- [ ] ...

## 一句话记忆
> ...
```

**统一的收尾三件套（必须都有）：**

| 收尾 | 作用 |
|---|---|
| **自检清单** | 可打勾，判断"这节过没过" |
| **一句话记忆** | 复习时只读这一段 |
| **易错点 / 反例**（有则加） | 提前埋伏，省得踩坑 |

### 4.1 「值得回看」只写"过程型"内容

**笔记能写结论，写不了过程。** 这个字段只用来标那些"文字替代不了"的位置：

| ✅ 值得标 | ❌ 不用标 |
|---|---|
| 老师**当场演算**（手推公式、算进制转换） | 概念定义的讲解（正文表格已经说清） |
| **调试器操作**（设断点、单步、看监视窗口） | 纯口述的原理 |
| **现场演示**（改代码看结果、打开生成的文件） | 课上的口头强调 |
| **用别的软件类比**（记事本演示 `\r`、Excel 演示 `\t`） | 顺带提一句的扩展知识 |

**只写一句话、一条即可。** 某些讲确实没有过程型内容，就写"纯讲解，看笔记就够，不必回看"。

> ❌ **不要**摘录老师原话做成对照表 —— 那是重复正文，已经全删（2026-11-06）。
> 详见第 5.4 节留下的那条结论。

## 5. 逐字稿：来源与三种用途

### 5.1 位置

```
C:\Users\18369\Documents\ZhuangFengYuan\408逐字稿\
└── 第N章\
    └── [序号]--NN_M_描述.doc
```

例：`第2章\[5]--02_1_程序员视角当中的计算机.doc`

- `[5]` = 全局导出序号
- `02_1` = 第 2 章第 1 讲
- 后缀是 `.doc`，但**实际是 DOCX**（文件头 `PK\x03\x04`）

### 5.2 三种用途（都很重要）

| 用途 | 怎么用 |
|---|---|
| **① 整理依据** | 笔记的骨架、举例、术语都从逐字稿来 |
| **② 校对依据** | **AI 会产生幻觉。**凡涉及概念定义、术语、数字，以老师原话为准；发现 AI 说法和逐字稿冲突，标出来 |
| **③ 视频定位** | 笔记头部记录讲次 → 对应百度网盘里第几章第几讲 → 回看视频对应片段 |

> **第 ③ 条是这套规范的独特价值**：笔记不只用来读，还能"倒查回视频"。

### 5.3 网盘视频与逐字稿是一一对应的

网盘目录：`01.27考研王道【C语言入门课程】/0N.第N章/`

**同一讲的两个文件同名，只有后缀不同：**

```
[5]--02_1_程序员视角当中的计算机.doc   ← 逐字稿（本地也有一份）
[5]--02_1_程序员视角当中的计算机.mp4   ← 视频（只在网盘）
```

**所以命名规律只有一条：把逐字稿的 `.doc` 换成 `.mp4`，就是视频文件名。**

笔记头部要写**完整的网盘相对路径**，才能一步定位：

```markdown
> **逐字稿**：`C:\Users\18369\Documents\ZhuangFengYuan\408逐字稿\第2章\[5]--02_1_程序员视角当中的计算机.doc`
> **视频**：网盘 `01.27考研王道【C语言入门课程】/02.第二章/[5]--02_1_程序员视角当中的计算机.mp4`
```

> 章节目录名格式：`0N.第N章`（如 `01.第一章`、`02.第二章`）。
> `01.第一章` 尚未实际确认，是按 `02.第二章` 的规律推的。

### 5.4 文稿面板可点击跳转（知道一次就行，别每篇都写）

**网盘播放器右侧有「文稿」面板，里面的文字与视频时间轴同步：点哪句，视频就跳到哪一帧。**

**用法**：打开视频 → 右侧「文稿」→ `Ctrl+F` → 粘贴你在笔记里看到的任意一句话 → 点中那句 → 视频跳到对应画面。

> **这条只记在这里，不在每篇笔记里重复。**

#### ⚠️ 已废弃：每篇结尾的「原文锚点」表

**曾经**在每份笔记结尾放一张「老师原话 / 说的什么」对照表，理由是"可以搜索原话精确跳转"。**2026-11-06 全部删除**（17 篇、184 行、98 条摘录）。

**删除原因**：

| 当初的理由 | 为什么站不住 |
|---|---|
| 摘原话能精确定位到秒 | 一讲只有 10~20 分钟，**"第几讲 + 视频路径"已经够定位**，不需要秒级 |
| 帮理解 | 摘的都是**概念定义句**，正文用表格讲得更清楚——读摘录等于把刚看过的内容再读一遍 |
| 提供索引 | 笔记本身就是那一讲的摘要，摘录表只是**重复一遍结构** |

**唯一有价值的两样东西被留下了**：

| 留下什么 | 放在哪 |
|---|---|
| 老师**现场演算 / 调试器操作 / 现场演示**的位置 | 笔记头部的 **`> 值得回看：`** 一行（见 4.1） |
| **ASR 口误**对照（文稿把 X 写成 Y） | 笔记头部的 **`> ⚠️ 文稿口误：`** 一行，或正文对应位置 |

### 5.5 校对时的三档判定（**别把「简化」当「错」**）

老师讲课会用**简化说法**。发现"老师说的和我以为的不一样"时，先分三档——**不能直接判错**：

| 档 | 什么情况 | 怎么处理 |
|---|---|---|
| **① 真错** | 事实性错误，照做会出 bug | 标明「⚠️ 此处与原话不同」，**写清正确说法**，原话仍可查 |
| **② 简化** | 为教学省略了前提 / 边界 | **原话保留**，旁边**补上边界条件**<br>（例："未初始化 = 垃圾值"只对**局部变量**成立，全局/static 自动为 0） |
| **③ 粒度不同** | 两个说法在**不同层级上都是对的** | **两个都写**，并说明各自属于哪层<br>（例："项目是编译的最小单位" vs "翻译单元是编译器逐个处理单位"） |

**❌ 禁止**：把老师的原话直接改成我的说法，或判它"措辞不准"。
**✅ 正确**：原话留着，把差别的**层级或边界**写清楚——读者要看到两种说法的关系，不是只看到我的结论。

> **踩过的坑（2026-11-07）**：老师说"项目是编译的最小单位"（IDE 粒度，对的），我改判成"措辞不准，编译最小单位是 `.c` 文件"（编译器粒度）。
> 其实两句话**都对**，只是层级不同。把"层级不同"说成"对方错了"，是最容易犯也最伤信任的一种错。

## 6. 整理流程（六步）

```
① 列目录 —— 确认这一章有哪几讲，讲次和标题
② 提取   —— python-docx 导出成 UTF-8 文本
③ 通读   —— 提炼骨架，判断该拆几份
④ 拆分   —— 按主题拆成 NN 主题.md，一份一个主题
⑤ 装配   —— 加逐字稿来源、上下篇链接、自检清单、一句话记忆
⑥ 校验   —— 跑一遍链接检查，确认没有死链
```

**拆分原则**：宁可多一份，不要一份塞满。

> **超过 300 行时**先检查它是不是混了两个主题——**混了就拆**。
> 单一主题即使超过 300 行也**不要强行拆**（比如第 2 章第 4 讲，内存模型本身就是个大主题，355 行是合理的）。

## 7. 已知的坑（踩过的）

| 坑 | 表现 | 解法 |
|---|---|---|
| **`.doc` 其实是 DOCX** | python-docx 能打开，但有人按老式 .doc 处理会失败 | 看文件头 `PK\x03\x04` 就按 DOCX 处理 |
| **中文 stdout 乱码** | 提取结果打印成 `????` | **写到 UTF-8 文件再用 read 读**，不要靠 stdout |
| **只读会话写不了 TEMP** | `Set-Content` 报 `PermissionDenied` | 临时文件放**工作区内** `.tmp/`，需要放宽权限 |
| **ConstrainedLanguage 禁用 .NET 静态方法** | `New-Object System.Text.UTF8Encoding` 报错 | 改用 cmdlet（`Set-Content -Encoding UTF8`） |
| **链接写法不对** | 点击提示"找不到文件" | **裸空格**，不加 `<>`、不写 `%20`（见第 8 节） |
| **相对路径层级算错** | 从 `第2章/` 跳到模块根要用 `../../` | 逐段核对 |

## 8. 链接写法

**文件名里有空格，链接里就原样写空格——不加尖括号，不做 `%20` 编码。**

```markdown
✅ [上一讲](02 用调试器验证程序运行.md)
✅ [模块导读](../00 C语言模块导读.md)
❌ [上一讲](<02 用调试器验证程序运行.md>)      ← Typora 里点不动
❌ [上一讲](02%20用调试器验证程序运行.md)      ← 点不动
```

> **这条是实测出来的**（2026-10-26 用 Typora 验证）：
> `[01 环境搭建与第一份C代码](第1章/01 环境搭建与第一份C代码.md)` ✅ 能跳
> 加尖括号、或写成 `%20` ❌ 跳不了。
>
> 虽然 CommonMark 规范推荐尖括号写法，但**以实际编辑器能跳为准**。

**相对路径速查（从 `408/C语言/第2章/xx.md` 出发）**

| 想跳到 | 写 | 层级说明 |
|---|---|---|
| 同章其他笔记 | `02 用调试器验证程序运行.md` | 同目录，直接写 |
| **模块导读** | `../00 C语言模块导读.md` | 上 **1** 层到 `C语言/` |
| 第1章某篇 | `../第1章/01 环境搭建与第一份C代码.md` | 上 1 层，再进 `第1章/` |
| **规范文档** | `../../00 408笔记规范.md` | 上 **2** 层到 `408/` |
| 学习计划 | `../../../学习计划.md` | 上 3 层到笔记根目录 |

> **算层级的方法**：把当前文件所在目录当起点，`..` 上跳一层。
> `408/C语言/第2章/` → `..` = `408/C语言/` → `../..` = `408/` → `../../..` = 笔记根目录。

## 9. 内容质量标准

一份合格的笔记应该做到：

- [ ] **开头给结论**（"这一讲讲什么"不超过 3 句）
- [ ] **能用表格就不用大段文字**（对照关系、参数、术语）
- [ ] **每个概念都有例子**（最好用课上的原例）
- [ ] **易混概念做显式对照表**（如 `=` vs `==`、标识符 vs 关键字）
- [ ] **老师没讲但对理解有用的内容，标"补充"**（不能让学生以为课上讲过）
- [ ] **结尾有自检清单 + 一句话记忆**
- [ ] **头部有逐字稿来源**（可倒查视频）
- [ ] **没有死链**
