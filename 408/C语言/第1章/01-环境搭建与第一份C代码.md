## 本章学什么

用一句话概括：**把「写代码 → 跑起来 → 能调试」这条链路走通。**

这一章不讲语法，只解决三件事：

1. 代码放在什么结构里（解决方案 / 项目 / 源文件）
2. 第一份 C 代码长什么样、每一行干什么
3. 出问题时怎么用调试器看

> 这一章是后面所有内容的地基。**调试器学不会，后面学数据结构会非常痛苦**——因为你只能靠"猜"和"打印"来查错。

## 一、项目结构：解决方案 vs 项目

### 1.1 VS 2022 里的三层结构

```
解决方案 Solution（一个文件夹 / 最大的容器）
  └─ 项目 Project（一份代码放一个项目）
       └─ 源文件 Source Files（.cpp 文件放这里）
```

**关键概念：**

| 概念       | 是什么             | 说明              |
| -------- | --------------- | --------------- |
| **解决方案** | 一个**文件夹**，最大的容器 | 里面可以放很多个项目      |
| **项目**   | 一份代码的载体         | **一份代码 = 一个项目** |
| **源文件**  | 项目里放 `.cpp` 的地方 | 代码写在这里          |

**推论：写了三个代码，就要建三个项目，但可以放在同一个解决方案里。**

> 命名习惯：C 语言一般从 0 开始计数。所以项目名常叫 `000_hello`、`001_hello`……

### 1.2 创建步骤（VS 2022）

1. 开始菜单搜 `VS 2022` → 打开
2. 欢迎界面选 **创建新项目**
3. 语言选 **C++**（不是 C，原因见第二节）
4. 模板选 **空项目** → 下一步
5. 填 **解决方案名称** + **项目名称** → 创建
6. 右侧「解决方案资源管理器」→ 右键 **源文件** → 添加 → **新建项**
7. 选 **C++ 文件**，命名为 `main.cpp` → 添加
8. 编辑器打开，开始写代码

> 界面乱了不要紧：可以重置窗口布局。解决方案资源管理器的页签可以拖动位置。

### 1.3 为什么要有「解决方案」？CLion 为什么没有？

**先说结论：解决方案不是 C 语言的组成部分，它是 Visual Studio 自己发明的"收纳盒"。**

三层的真实关系：

| 层级       | 本质是什么                          | 编译需要它吗           |
| -------- | ------------------------------ | ---------------- |
| **解决方案** | 一个文件夹 + `.sln` 文件，记录"里面有哪几个项目" | ❌ **不需要**        |
| **项目**   | 一套能编译出程序的配置（`.vcxproj`）        | ✅ 需要，**编译的最小单位** |
| **源文件**  | `.cpp` 代码                      | ✅ 真正的内容          |

**编译器只认「项目」，不认「解决方案」。**

解决方案的唯一作用：你写了 100 个练习程序（= 100 个项目）时，能**一次性打开、一次性构建**。它就是个**批量管理工具**。

> 类比：解决方案像书架，项目是书。书架方便一次搬很多书，但**读一本书并不需要书架**。

**CLion 为什么没有这一层？**

因为 CLion 用的是 **CMake** 构建系统，CMake 的世界里只有两层：

```
项目（CMakeLists.txt） → 目标 target（可执行文件 / 库）
```

**CMake 本身就没有"解决方案"这个概念**，所以 CLion 自然也没有。

**CLion 里想管多个程序怎么办？**

1. 一个项目里放多个源文件，用 `add_executable()` 定义多个 target（最常用）
2. 用 `add_subdirectory()` 把子项目挂进来

**对你的实际影响：零。** 学习阶段一次只写一个程序，一个项目就够。

> 你可能没注意：**VS 里只建一个项目时，它会自动用项目名建一个同名解决方案**，所以平时几乎感觉不到它存在。它是在"项目变多"时才显出作用的。

### 1.4 VS 与 CLion 界面操作对照

|          | VS 2022         | CLion                       |
| -------- | --------------- | --------------------------- |
| 层级       | 解决方案 → 项目 → 源文件 | **项目 → 源文件**（无解决方案）         |
| 新建入口     | 创建新项目 → 空项目     | 欢迎界面 **+** → C++ Executable |
| main.cpp | 要手动新建           | **自动生成**（内容可全删掉重写）          |

> CLion 自动生成的 main.cpp 里有一堆模板内容，**直接全删掉**，写自己的。

## 二、为什么学 C 语言，却新建 .cpp 文件？

这是本章第一个需要理解、而不是记住的点。

**结论：完全可以用 C++ 编译器编译 C 代码，而且更方便。**

理由：

1. **C++ 是 C 的超集**（视频里叫"超级"）。C 支持的语法，C++ 全都支持。
2. 所以 **`.cpp` 文件里写纯 C 代码，没有任何问题**。
3. **为什么不用 .c 而用 .cpp？** 因为后面准备机试时，会用到一些 **C 语言没有、C++ 才有**的特性（比如更顺手的输入输出、容器等），那时候用 C++ 就省事。
4. 为将来方便，**从一开始就用 C++ 编译器**。

> ⚠️ 常见误解：以为"学 C 就必须建 .c 文件"。不是的——语言和文件后缀不是绑死的。

## 三、第一份代码：hello world

### 3.1 代码

```c
#include <stdio.h>

int main()
{
    printf("hello world\n");
    return 0;
}
```

### 3.2 逐行解释

| 行   | 代码                         | 作用                                                      |
| --- | -------------------------- | ------------------------------------------------------- |
| 1   | `#include <stdio.h>`       | **头文件**。`stdio` = standard input/output，`printf` 的声明在这里 |
| 3   | `int main()`               | **主函数**，程序的入口。`int` 表示返回整数，`()` 里放参数                    |
| 4   | `{`                        | 函数体开始                                                   |
| 5   | `printf("hello world\n");` | 输出。`\n` 是**换行**，`;` 是语句结束                               |
| 6   | `return 0;`                | 返回 0，表示程序正常结束                                           |
| 7   | `}`                        | 函数体结束                                                   |

**几个必须注意的点：**

- `int` 和 `main` 之间有空格
- **每条语句以 `;` 结尾**（花括号不是语句，不用分号）
- `\n` 是转义字符，不是两个字符
- 引号是**英文引号**，中文引号会报错（新手最常犯的错）

### 3.3 运行 & 验证

**VS：** 点绿色三角形（本地 Windows 调试器），或菜单「调试 → 开始调试」，或按 **F5**。

**预期输出：**

```
hello world

```

> ⚠️ **输出是两行**：`hello world` 一行，后面跟着一个空行——这是 `\n` 造成的。看到两行说明正常。
> 如果没报错、弹出了这个黑框框、显示了这句话，**说明环境配好了**。

## 四、从代码到运行：中间发生了什么

### 4.1 流程图

```
写好源码 main.cpp
      │
      │ ① 编译（VS / 编译器帮我们做）
      ▼
可执行程序（.exe）
      │
      │ ② 操作系统创建进程
      ▼
进程运行
      │
      ▼
控制台输出 hello world
```

### 4.2 三个关键结论

**① 调试 ≠ 只是运行。调试 = 编译 + 运行。**

你点"开始调试"的时候，VS 先编译，编译成功才启动程序。所以：

> **只要能看到控制台窗口，就说明编译通过了。** 反过来说，弹不出窗口就是编译没过。

**② 那个黑框框叫「控制台进程」。**

黑底白字、弹出来的那个窗口，专业名字叫**控制台（Console）**，它对应操作系统里的一个**进程**。VS 只是启动它，真正创建进程的是**操作系统**。

**③ 输出内容是代码决定的，不是 VS 决定的。**

整个链条：**你写代码 → VS 编译 → 操作系统创建进程 → 进程按代码执行 → 输出结果。**

## 五、调试器：从"猜"变成"看"

这一节是本章最有价值的部分。

### 5.1 VS 与 CLion 对照

| 操作                | VS 2022        | CLion             |
| ----------------- | -------------- | ----------------- |
| **开始调试**          | 绿色**三角形** / F5 | 绿色**虫子**（不是三角形！）  |
| **加/取消断点**        | 行号左侧点一下 / F9   | 行号左侧点一下 / Ctrl+F8 |
| **步过**（Step Over） | **F10**        | **F8**            |
| **步入**（Step Into） | **F11**        | **F7**            |
| **继续运行**          | F5             | F9 / 点恢复          |
| **停止调试**          | Shift+F5       | 红色正方形             |

> ※ 视频里念 VS 快捷键时数字有误（把步过说成 F9），**以本表为准**。
> 记住本质：**VS 用 F10/F11，CLion 用 F8/F7，都是「先过、后入」。**

### 5.2 断点（Breakpoint）

鼠标移到行号上点一下 = **加断点**，再点一下 = **取消断点**。

程序会**跑到断点处停下来**，这时候你才能看变量的值。

### 5.3 步过 vs 步入（重点，后面学函数必用）

|       | 步过 Step Over          | 步入 Step Into     |
| ----- | --------------------- | ---------------- |
| 行为    | **跳过函数**，把整个函数当作一步执行完 | **进入函数内部**，一行一行看 |
| CLion | F8                    | F7               |
| VS    | F10                   | F11              |
| 什么时候用 | 这个函数我信它，不想看           | 这个函数出问题了，要看里面    |

> 现在还没学到函数，所以两者效果看起来一样。**学到函数再回来体会**——但快捷键现在就记住。

### 5.4 CLion 调试界面四个窗口

| 窗口                    | 作用                           | VS 里的对应 |
| --------------------- | ---------------------------- | ------- |
| **线程和变量**             | 看变量当前值                       | 监视窗口    |
| **控制台**               | `printf` 的输出显示在这（**内置**，不弹窗） | 单独弹出的黑框 |
| **内存视图**              | 看变量在内存里长什么样                  | 内存窗口    |
| **调用堆栈**（thread 那一竖块） | 看函数调用链                       | 调用堆栈    |

**添加监视：** 在「监视」里输入变量名（`i`）或取地址（`&i`），点「添加到监视」。

**看内存：** 内存视图里输入 `&i` → 查看。

### 5.5 用一段代码练习单步

```c
#include <stdio.h>

int main()
{
    int i = 1;          // ← 断点打在这一行
    i = i + 2;
    i = i + 3;
    i = i - 4;
    printf("i = %d\n", i);
    return 0;
}
```

**跟着单步走一遍，观察 `i` 的变化：**

| 执行到             | `i` 的值        |
| --------------- | ------------- |
| `int i = 1;` 之后 | `1`           |
| `i = i + 2;` 之后 | `3`           |
| `i = i + 3;` 之后 | `6`           |
| `i = i - 4;` 之后 | `2`           |
| `printf` 之后     | 控制台显示 `i = 2` |

> `%d` 是整数的格式占位符，对应后面的 `i`。

## 六、一个必须记住的坑：未初始化的变量是垃圾值

在断点停在 `int i = 1;` **之前**时，去看 `i` 的值——会发现是**一个乱七八糟的数**（比如 `0x16d72b4c8` 这个地址里的内容）。

**原因：局部变量如果不赋初值，它的值是内存里残留的垃圾数据，不确定。**

这一点在 C 语言里是核心概念，后面会反复遇到：

- 变量**声明了不等于初始化了**
- 用未初始化的变量是**未定义行为（UB）**
- 所以好习惯是：**声明时立刻给初值**（`int i = 0;`）
