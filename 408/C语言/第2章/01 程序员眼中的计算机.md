## 一个需要先换个问法的问题

**「什么是计算机？」这个问题太大。**

要回答它，得从每个器件怎么设计、怎么制造、原理是什么讲起——讲几天几夜讲不完。

所以程序员要做的第一件事是**抽象**：

> **把复杂的、但对你没用的细节隐藏起来，提炼出真正有用的核心要素。**

换成一个程序员该问的问题：

> **我们如何理解计算机？怎么用它来完成我们的任务？**

## 从算盘开始推演

计算机是**模拟人类思考和运算过程**的机器。但能算数的机器我们很早就有——**算盘**。

那就从算盘开始，看看它离现代计算机还差多远。

### 第一步：算 `1 + 2`

**需要什么**：一把算盘 + 一个会打算盘的人。

**过程**：

1. 把两个操作数（1 和 2）和运算（加法）告诉这个人
2. 他按算盘规则拨珠子
3. 得到结果 3

**结论**：算盘 + 人，能完成**两个数**的运算。✅

### 第二步：算 `1 + 2 + 3 - 4`

**直接算不行。** 为什么？

> **算盘只会两个数的运算。** 这个"训练有素的人"只被训练过两数运算，没有三数、四数运算的规则。

### 第三步：加一张草稿纸

要算复杂表达式，必须在算盘之外**再加一个设备**——**草稿纸**。

**草稿纸上记两样东西：**

| 记什么 | 例子 |
|---|---|
| **中间数据** | 一、二、三、四（参与运算的数，以及每一步的结果） |
| **每一步要做什么的指令** | 第一步做加法、第二步做加法、第三步做减法 |

**为什么草稿纸能解决问题？** 因为可以**把复杂表达式拆成一系列两数运算**：

```
1 + 2 + 3 - 4
  ↓ 拆成
(1 + 2) = 3        ← 算盘算
(3 + 3) = 6        ← 算盘算
(6 - 4) = 2        ← 算盘算
```

每一步都只有两个数参与运算——**算盘又能干活了**。

### 第四步：还需要一个人（周期性重复）

光有算盘 + 草稿纸还不够，还需要一个**周期性地做同一套动作**的人：

```
① 看指令区：这一步要干什么？（加法）
② 从草稿纸取数：谁和谁加？（一 和 二）
③ 交给算盘：算一下
④ 把结果写回草稿纸：3，覆盖掉原来那个 1
⑤ 重复：看下一条指令……
```

**注意第 ④ 步的细节**：结果是**覆盖写回**原来的位置（把草稿纸上的"一"擦掉，写上"三"）。

## 映射到真正的计算机

把上面三个角色换成现代器件：

| 算盘类比 | 计算机里的东西 | 干什么 |
|---|---|---|
| **草稿纸** | **存储器（内存）** | 存**要运行的指令** + **运行过程中产生的数据** |
| **算盘** | **CPU（中央处理器）** | 做运算：加减乘除、取余、逻辑判断（比大小、判断真假） |
| **那个重复做事的人** | **时钟（CPU 内部）** | 滴答滴答不停，驱动"取指令 → 解释 → 执行 → 写回"的循环 |

于是得到这一章最核心的结论：

> ## 程序员眼中的计算机 = CPU + 存储器

**时钟做的事，就是那个人的事**：

```
取出指令  →  解释指令  →  交给运算设备  →  把结果写回存储器
   ↑                                              │
   └──────────────── 循环 ────────────────────────┘
```

---

## 这个模型的实际用法

**写代码时只需要抓住两件事：**

| 抓什么 | 问自己 |
|---|---|
| **CPU 怎么工作的** | 这条指令会被怎么执行？顺序是什么？ |
| **存储器里有什么数据** | 现在内存里有哪些变量？值是多少？ |

至于 CPU 内部怎么实现、存储器内部有什么坑——**那些留给「计算机组成原理」**。现在只要有个基本印象。

---

## 一个补充（老师没讲，但值得知道）

这个「程序和数据都放在同一块存储器里」的模型，有个正式名字叫**冯·诺依曼结构**（存储程序计算机）。

它的两大特征正好对应这一章：

1. **指令和数据放在同一个存储器里**（草稿纸既存指令又存数据）
2. **CPU 按顺序从存储器取指令执行**（那个人的周期动作）

> 学了这一章，你其实已经理解了现代计算机最基础的架构模型。名字可以在「计算机组成原理」里再正式见面。
