## 三、打断点

**操作**：把鼠标移到**行号左边**，单击一下。

行号左侧出现一个**红点**，这就是**断点**。

### 断点的语义（非常重要）

> **断点表示：程序运行到这一行时，在这行执行之前停下来。**

这一句话能解决本章一个最大的困惑（见第五节）。

## 四、整理调试界面

点调试（F5）后，VS 会从"代码编辑状态"切换到"调试状态"，弹出的窗口太多，要精简：

| 窗口 | 处理 |
|---|---|
| 自动窗口 | **关掉** |
| 局部变量 | **关掉** |
| 断点 | **关掉** |
| 异常设置 | **关掉** |

菜单 **调试 → 窗口 → 内存 → 内存 1**。

拖动它的标题栏（那个十字架位置）可以调整位置和宽度。

## 五、看变量和内存

### 5.1 在监视窗口输入 `i`

看到的值是 **`696`**（你那里可能是别的数）。

### 5.2 为什么是 696？——本讲最大的坑

**你的第一反应可能是**：断点打在第 3 行（`int i = 1;`），那 `i` 不就是 1 吗？怎么会是 696？

**原因**：

```
断点停在第 3 行 = 第 2 行已经执行完，第 3 行还没开始

第 2 行是 int main()    →  函数声明
第 3 行是 int i = 1;    →  这行还没执行

既然 int i = 1; 还没执行，i 就没有被初始化
→  里面是内存里残留的垃圾数据  →  696
```

> **这是 C 语言的核心概念**：变量**声明了不等于初始化了**。未初始化的局部变量里是**垃圾值**，不确定。

### 5.3 看地址：`&i`

在监视窗口输入 **`&i`**（取地址：and i，读作"与 i"或"按位与 i"，这里是**取地址运算符**）。

把它拖到**内存窗口**里。

**内存窗口显示了什么？**

```
0x012FFA00  01 00 00 00  ....
           ↑  ↑
        这里就是 i 所在的那个字节
```

> `&i` 的含义、"地址"到底指什么，第 4 讲会详细展开。现在照做即可。

## 六、单步观察（本讲的高潮）

### 6.1 操作

按 **F10**（**逐过程 / Step Over**），或者点工具栏那个「逐过程」按钮。

### 6.2 每按一次，看**两个地方**

1. **左下角监视窗口**里 `i` 的值
2. **右边内存窗口**里那个字节的内容

### 6.3 观察记录

| 按 F10 后执行到的语句 | 监视窗口 `i` | 内存窗口那一字节 |
|---|---|---|
| （断点处，第 3 行未执行） | `696`（垃圾值） | 乱值 |
| `int i = 1;` | **1** | **01** |
| `i = i + 2;` | **3** | **03** |
| `i = i + 3;` | **6** | **06** |
| `i = i - 4;` | **2** | **02** |

**两处同步变化**——这就是"CPU 运算完把结果写回存储器"的直接证据。

## 七、这一讲到底证明了什么

回过头看第 1 讲的模型：

| 模型里的东西 | 调试器里看到的 |
|---|---|
| 存储器存**数据** | 内存窗口里那个字节（01 / 03 / 06 / 02） |
| 存储器存**指令** | 程序代码本身（也是个存储区） |
| CPU 周期性**取指、执行、写回** | 每按一次 F10，就前进一条语句，内存随之变化 |

**所以：计算机对程序员而言，就是一个"存指令 + 存数据 + 按顺序执行"的机器。**

老师原话的意思是：他不是在编故事，**你亲眼看到了**。
