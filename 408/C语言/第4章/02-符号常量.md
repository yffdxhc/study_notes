## 这一讲讲什么

**符号常量 = 给字面值常量起个名字**，用 `#define` 实现，靠**宏**在**预处理阶段**做**文本替换**。

它解决了魔法数（改一处、全改），但引入了新坑：**只替换、不检查**——所以宏里的表达式**必须加括号**。

---

## 一、怎么写

```c
#define R   3      // 宏定义之间一般用空格对齐
#define PI  3
```

| 要点 | 说明 |
|---|---|
| 开头 `#define` | 这是**预处理指令**，不是 C 语句 |
| `#define` 和名字之间**有空格** | |
| 名字和值之间**有空格** | |
| **末尾不加分号** | 加了分号，分号会被一起替换进代码 |
| 命名习惯用**大写** | `R`、`PI`，一眼看出是常量 |

> **为什么末尾没有分号**：这行代码**根本不交给编译器**——它在预处理阶段就被替换掉了。`;` 是 C 语句的结束符，这里没有语句。

---

## 二、立刻见效的好处

```c
// 用字面值
printf("r=%d, a=%d", 3, 3 * 3 * 3);     // 改半径要改对位置

// 用符号常量
printf("r=%d, a=%d", R, PI * R * R);    // 改半径只改 #define 一行
```

**把半径从 3 改成 4**：只改 `#define R 4` 一处。

| | 改之前 | 改之后 |
|---|---|---|
| `R` | 3 | **4** |
| `PI` | 3 | **3（不受影响）** |
| 结果 | 27 | **48**（3×4×4） |

> **这就是符号常量的价值：把"这个数字是什么"从代码里挪到了名字里。**

## 三、背后的机制：预处理与宏

### 3.1 代码生成流程

```
xxx.cpp  ──预处理──▶  xxx.i  ──编译──▶  可执行程序
              ↑
        宏在这里被替换
```

> **预处理发生在编译之前。** 宏的工作就是"在你把代码交给编译器之前，先做文本替换"。

### 3.2 亲眼看预处理结果（实操，值得做一遍）

| 步 | 操作 |
|---|---|
| 1 | 右键**项目** → 属性 |
| 2 | C/C++ → 预处理器 → **预处理到文件** → 改成「是」 |
| 3 | 右键 → 生成 |
| 4 | 右键 → 在文件资源管理器中打开文件夹 → `x64\Debug\` 下找 **`.i` 文件** |
| 5 | 把 `.i` 拖进 VS，**拉到文件末尾** |

**看到两件事**：

| 现象 | 说明 |
|---|---|
| **注释全被删掉了** | 预处理阶段就清掉 |
| **宏全被替换成了原值** | 文本替换的直接证据 |

> ⚠️ 勾了「预处理到文件」之后**不会再继续编译**，所以那句"报错"可以先不管。做完记得**改回「否」**。

## 四、坑：只替换，不计算，不检查

### 4.1 复现

把半径写成 `3+1`（本来是 4）：

```c
#define R   3+1        // ❌ 没加括号
```

**期望**：`PI * R * R` = 3 × 4 × 4 = **48**
**实际**：预处理只做文本替换 → 表达式变成：

```c
3 * 3+1 * 3+1          // = 9 + 3 + 1 = 13  ❌
```

**结果算出 13**，而不是 48。

### 4.2 原因

| 环节 | 是否发生 |
|---|---|
| 文本替换 | ✅ 只做这个 |
| **把 `3+1` 先算成 4** | ❌ **不做** |
| **编译检查 / 类型检查** | ❌ **不做** |

> 替换进去的是裸的 `3+1`，**乘法的优先级比加法高**，所以先算了 `3*3`。

### 4.3 正确写法：宏里的表达式一律加括号

```c
#define R   (3+1)      // ✅
```

**加括号后**：`PI * (3+1) * (3+1)` = 3 × 4 × 4 = **48** ✅

> **规则：宏定义里只要出现表达式，就给整个表达式加括号。** 这是硬性要求，不是风格问题。

## 五、总结：常量的全貌

| 常量 | 种类 | 说明 |
|---|---|---|
| **字面值常量** | 4 种 | 整数 `1234`、浮点 `3.14`、字符 `'a'`、字符串 `"abc"` |
| **符号常量** | 1 种 | `#define 名字 值`，靠宏实现 |

**该怎么选**：

> **尽量少用字面值常量（有魔法数问题），多用符号常量。**

---

## 易错点

| 易错点 | 后果 | 正确做法 |
|---|---|---|
| `#define R 3;` 末尾加分号 | 分号被替换进代码，可能出现莫名其妙的语法错误 | **不加分号** |
| 宏里表达式不加括号 | **优先级被破坏**，算出错误结果（48 变 13） | `#define R (3+1)` |
| 以为宏会做类型检查 | 宏只是文本替换，类型错误到编译阶段才暴露 | 记住"**只替换**" |
| 以为预处理在编译之后 | 顺序是 **预处理 → 编译 → 链接** | 预处理在最前 |
| 忘了改回「预处理到文件 = 否」 | 后面一直不编译，白折腾 | 演示完立刻改回 |
