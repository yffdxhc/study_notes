## 这一讲讲什么

两件事拼成一条链：

1. **写一个整数时，它的"进制"由开头决定**（`0` = 八进制、`0x` = 十六进制）
2. **每种整数类型能表示多大范围** —— 由它占多少比特决定，公式 `[-2^(n-1), 2^(n-1)-1]`

最后给一个**超实用的估算技巧**：`2^10 ≈ 1000`，所以 `int` 大约是 ±20 亿。

---

## 一、整型字面值：进制由开头决定

### 1.1 三种写法

| 写法 | 进制 | 字面值 | 实际十进制值 |
|---|---|---|---|
| `1234` | **十进制** | `1234` | 1234 |
| **`0` 开头** | **八进制** | `01234` | **668** |
| **`0x` 开头** | **十六进制** | `0x1234` | **4660** |

验证：

```c
printf("%d", 01234);    // 输出 668   ← 不是 1234！
printf("%d", 0x1234);   // 输出 4660
```

> **⚠️ 最容易踩的坑：`0` 开头就是八进制，不是"前面补零不影响数值"。**
> 数学上补零无影响，C 语言里**彻底换了进制**。

### 1.2 八进制能用的数字：只有 0–7

```c
012348;    // ❌ 报错：无效的八进制数
```

**原因**：`8` 超出八进制能表示的数字范围。

### 1.3 十六进制能用的数字：0–9 + a–f

| 可以 | 不可以 |
|---|---|
| `0x1234` `0xfff` `0xabcd` | `0xg` ❌ |
| 小写 `a-f`、大写 `A-F` 都行 | `g` 及之后的字母 |

## 二、有符号整数：按占内存从小到大

### 2.1 排序

```
char  <  short  <  int  <  long  <  long long
```

### 2.2 实测大小（VS，x64）

**怎么看**：随便找个程序 → 打**断点** → 开始调试 → 在**监视窗口**里输入 `sizeof char`、`sizeof short` …

| 类型 | 字节数 |
|---|---|
| `char` | **1** |
| `short` | **2** |
| `int` | **4** |
| `long` | **4** |
| `long long` | **8** |

### 2.3 ⚠️ 这些长度不是固定的

> **`int` 和 `long` 的长度在不同平台上会变。**

| 情况 | 说明 |
|---|---|
| 某些平台上 `int` 可能只有 **2 字节** | |
| 某些平台上 `long` 可能有 **8 字节** | |

> 所以写代码时**不要假设** `int` 一定是 4 字节；跨平台时要查该平台的实现（或用 `sizeof` 实测）。

## 三、数据范围怎么算

### 3.1 从比特数推可能性

以 `int`（4 字节 = **32 比特**）为例：

```
32 比特 → 2^32 种 0/1 组合
```

### 3.2 这些组合怎么分给"负数 / 0 / 正数"

| 类别 | 占多少种 |
|---|---|
| **零** | **1 种** |
| **负数** | **2^31 种** |
| **正数** | **2^31 − 1 种** |

> 正负**大致各占一半，但负数多一种**（因为 0 占掉了一个位置）。

**加起来**：`1 + 2^31 + (2^31 − 1) = 2^32` ✅

### 3.3 数轴

```
       最小                       0                     最大
   −2^31  ←───────────────────  0  ───────────────────▶  2^31 − 1
 (−2147483648)                                        (2147483647)
```

### 3.4 通用公式（重点）

> **n 个比特的有符号整数，范围是 `[−2^(n−1), 2^(n−1) − 1]`**

| 类型 | 比特 n | 范围 |
|---|---|---|
| `char` | 8 | **−128 ~ 127** |
| `short` | 16 | 约 **±3 万多**（−32768 ~ 32767） |
| `int` | 32 | 约 **±21 亿** |

## 四、估算技巧：不用记 2^31 是多少

| 幂 | 近似值 | 记忆法 |
|---|---|---|
| `2^10` | **≈ 1000**（实际 1024） | 这是基准，记住这个就够 |
| `2^20` | ≈ 1000 × 1000 = **100 万** | 两个 2^10 |
| `2^30` | ≈ **10 亿** | 三个 2^10 |
| `2^31` | ≈ 10 亿 × 2 = **20 亿** | 2^30 再乘 2 |

> **结论：`int` 的值不要超过 20 亿，也不要小于 −20 亿。**

## 易错点

| 易错点 | 后果 | 正确理解 |
|---|---|---|
| 以为 `01234` 就是 `1234` | 值变成 668，**算错还不知道为什么** | `0` 开头 = **八进制** |
| 在八进制里写 8 或 9 | 编译报"无效的八进制数" | 八进制只有 0–7 |
| 在十六进制里写 `g` | 识别错误 | 只到 `f` |
| 假设 `int` 一定是 4 字节 | 跨平台出错 | **长度依平台而变**，用 `sizeof` 实测 |
| 背 `2147483647` | 记不住 | 用 `2^10 ≈ 1000` 估出 **±20 亿** |
| 以为正负范围对称 | 最大值和最小值的绝对值差 1 | `[−2^(n−1), 2^(n−1)−1]` |
