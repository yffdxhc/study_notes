## 这一讲讲什么

浮点数处理的**根本问题只有一个：它是近似值，不是精确值。**

由此推出三件事：**不能比较相等**、**float 精度只有 6 位**、**大数加小数会被吃掉**。

> 记住这句就够：**整数是精确的，浮点数是有误差的。**

---

## 一、两种类型与占位符

| 类型 | 字节 | 名称 |
|---|---|---|
| `float` | **4** | 单精度 |
| `double` | **8** | 双精度 |

**打印浮点用 `%f`**：

```c
float f = 3.14159f;
printf("f = %f\n", f);       // 默认打 6 位小数
```

| 占位符 | 用于 |
|---|---|
| `%f` | 浮点数 |
| `%d` | 有符号整数 |
| `%u` | 无符号整数 |
| `%c` | 字符 |

### 1.1 控制小数位数：`%.Nf`

```c
printf("f = %.10f\n", f);    // 小数点后打 10 位
```

> **格式：`%` `.` 数字 `f`** —— 中间那个".数字"就是小数位数。

---

## 二、核心区别：整数精确，浮点近似

### 2.1 实测

```c
float f = 3.14159;
printf("%.10f\n", f);
```

**期望**：`3.1415900000`
**实际**：`3.1415901184` ← **后面多了 `01184`**

> **你写进去的是 3.14159，存进去的不是。**

### 2.2 为什么会这样

| 事实 | 后果 |
|---|---|
| 计算机内存**有限** | 只能用有限位表示一个数 |
| 有些小数是**无限不循环**的（如 1/3 = 0.333…） | **永远存不完** |
| 存不完就只能存"最接近的那个" | 于是得到**约等于**，不是**等于** |

```
1/3 = 0.3333……（无限个 3）
内存里只能存 0.3333333（有限位）
→ 两者永远是「≈」的关系
```

## 三、推论 1：浮点数不能比较相等

```c
if (a == b) { ... }        // ❌ 危险
```

**原因**：两个浮点数之间**通常总有微小偏差**，`a == b` 很可能永远不成立，即使你觉得它们"应该相等"。

**正确做法**（后面会学）：比较它们的**差的绝对值**是否小于某个很小的阈值。

> **这是一条硬规矩：浮点数不要用 `==` 判断相等。**

---

## 四、推论 2：float 和 double 的精度差

| 类型 | 有效数字 |
|---|---|
| `float` | **约 6 位** |
| `double` | **约 15 位** |

**这解释了前面的例子**：`3.14159` 已经是 **6 位**有效数字，正好卡在 float 的极限上——所以第 7 位开始就不准了。

> **double 比 float 最大的优势：精度更高。**

```c
double d = 3.14159;
printf("%.10f\n", d);     // 3.1415900000  ← 明显更准
```

## 五、推论 3：精度丢失（大数 + 小数 = 大数）

### 5.1 复现

```c
float a = 1.2345e10;      // 科学计数法：1.2345 × 10^10
float b = a + 20;
printf("a = %f\nb = %f\n", a, b);
```

**期望**：`b` 比 `a` 大 20
**实际**：**`a` 和 `b` 打印出来完全一样**

### 5.2 原因

```
1.2345 × 10^10 = 12345000000      （11 位数）
                        + 20       （2 位数）
```

**加法要先"对齐小数点"**：把 20 右移到对应位置时，它已经**掉到 float 的精度之外**了——直接被忽略。

> **两个浮点数绝对值相差很大时做加减法，小的那个会被吃掉。**

### 5.3 解决：换成 double

```c
double a = 1.2345e10;
double b = a + 20;        // ✅ 这次 20 保住了
```

**因为 double 精度更高（15 位）**，能容下这个差值。

> 如果 double 也不够——这一讲先不讨论（那是数值分析的事）。

### 5.4 科学计数法写法

```c
1.2345e10      // = 1.2345 × 10^10
1.2345e9       // = 1.2345 × 10^9
```

> **`eN` = 乘以 10 的 N 次方。**

## 易错点

| 易错点 | 正确理解 |
|---|---|
| 用 `==` 比较两个浮点数 | **几乎永远不成立**，要比差值 |
| 用 `%d` 打印浮点 | 用 **`%f`** |
| 以为 `3.14159` 存进去就是 3.14159 | 是**近似值**，可能变成 3.1415901184 |
| 以为 float 足够精确 | 有效数字只有 **6 位** |
| 大数加小数，以为肯定能加上 | 差值超出精度就**被忽略** |
| 用 float 做精度要求高的运算 | 优先 **double** |

## 一句话记忆

> **浮点 = 近似值。内存有限，无限小数存不下，只能约等于。**
> **所以：不能 `==` 比较；float 只有 6 位有效数字、double 约 15 位；大数加小数，小的会被吃掉。**
> **打印用 `%f`，控制位数用 `%.Nf`。**
