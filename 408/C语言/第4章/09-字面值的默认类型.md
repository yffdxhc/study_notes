## 这一讲讲什么

**你写下的每一个字面值，都有一个"默认类型"** —— 这件事会静默毁掉你的计算。

两条默认规则：

| 你写的 | 默认类型 |
|---|---|
| 一个**整数** | **`int`**（放不下才升级） |
| 一个**浮点数** | **一律 `double`**（哪怕只有 3 位有效数字） |

由此引出两个经典事故：**`1/2 = 0`** 和 **`131072 * 131072 = 0`**。

---

## 一、整数字面值：默认 `int`，放不下就升级

**怎么看**：把鼠标悬停在数字上，VS 会显示它的类型。

```c
1;              // int
22亿;           // 超过 int 上限 → 升级
```

### 1.1 实测：十六进制看得很清楚

| 写法 | 位数 | 类型 |
|---|---|---|
| `0xf` 到 `0xfffffff` | 1~7 个 f | `int` |
| `0xffffffff` | **8 个 f** | **unsigned int** |
| `0xfffffffff` | **9 个 f** | **long long** |
| 再往后加 | | `unsigned long long` |
| 再加到一定程度 | | ❌ 报错：**整数常量太大** |

**十进制**：写到 **22 亿**量级时，类型也会变成 `long long`。

### 1.2 ⚠️ 为什么八/十六进制能升到 `unsigned`，十进制不行（补充）

这是 C 语言标准的规定，两条序列不同：

| 写法 | 升级顺序 |
|---|---|
| **十进制** | `int` → `long` → `long long`（**只走有符号**） |
| **八/十六进制** | `int` → `unsigned int` → `long` → `unsigned long` → `long long` → `unsigned long long` |

**这正好解释了两个实测**：

- `0xffffffff`（42 亿）→ int 放不下 → **`unsigned int`** 放得下 ✅
- 十进制 22 亿 → int 放不下 → long（32 位）放不下 → **`long long`** ✅（中间跳过了 unsigned）

> 这条是**补充内容**（老师只演示了现象没讲规则），但能解释为什么"同样是超一点，结果类型不一样"。

## 二、浮点字面值：一律 `double`

```c
3.14f      // float（加了 f 后缀）
3.14       // double（默认）
```

> **只要写浮点数，它就是 `double`** —— 哪怕有效数字只有 3 位。

**"有效数字只有 3 位，是不是 float？"** —— ❌ **不是**。这和有效数字无关，浮点字面值**默认就是 double**。

## 三、后果 1：整数除法 —— `1/2 = 0`

### 3.1 事故现场

```c
float f = 1 / 2;
printf("%f\n", f);      // 输出 0.000000  ← 不是 0.5！
```

### 3.2 为什么

```
1  →  int
2  →  int
1 / 2  →  两个 int 运算，结果也是 int
      →  1 ÷ 2 取整 = 0
      →  再把 0 赋给 float，得到 0.0
```

> **坑在"先算完再赋值"**：等号右边早就已经是 `0` 了，`float` 救不回来。

### 3.3 修正：让至少一个操作数变成浮点

```c
float f = 1.0 / 2;      // ✅ 0.5
```

**为什么这样就对了**：

```
1.0  →  double（浮点字面值默认 double）
2    →  int
混合运算 → int 先隐式转换成 double（值不变）
→ double ÷ double = 0.5
```

> **规则：只要有一个操作数是浮点，结果就是浮点。**

## 四、后果 2：中间结果溢出 —— `131072 * 131072 = 0`

### 4.1 事故现场

```c
long long ll = 131072 * 131072;
printf("%lld\n", ll);      // 输出 0 ！
```

**真实值**：131072² = **17,179,869,184**（171 亿）
**需要的位数**：**35 个比特**

### 4.2 为什么是 0

```
131072       → int
131072       → int
int × int    → 结果也是 int（32 比特）
             → 171 亿需要 35 比特，32 比特放不下 → 溢出
             → 溢出后的值（0）再赋给 long long
```

> **关键：溢出发生在赋值之前。** `long long` 有 64 比特完全够用，但它**来晚了**——信息在算乘法时就已经丢了。
>
> **丢掉的信息不会回来。**

### 4.3 修正：把至少一个操作数**先**转成 `long long`

用**类型转换（强制转换）运算符**：

```c
long long ll = (long long)131072 * 131072;      // ✅ 正确
```

**语法**：

```c
(类型) 表达式
```

**效果**：

```
(long long)131072  →  long long
131072             →  int，但和 long long 运算时会自动提升成 long long
结果               →  long long，64 比特装得下 171 亿 ✅
```

### 4.4 `long long` 的占位符是 `%lld`

```c
printf("%lld\n", ll);      // ✅
printf("%d\n", ll);        // ❌ 类型不匹配
```

## 五、两条通用规则

> **① 写整数 → 极可能是 `int`；写浮点 → 一定是 `double`。**
>
> **② 运算符两边都是 `int`，结果就一定是 `int`** —— 这跟数学不一样，尤其在除法上。

**所以做数学运算时**：

| 需求 | 建议 |
|---|---|
| 要小数结果 | 至少一个操作数用浮点（优先 `double`） |
| 大数相乘 | 先把一个操作数转成 `long long` |
| 一般数学计算 | **优先浮点类型，而不是整数类型** |

---

## 易错点

| 易错点 | 后果 | 正确做法 |
|---|---|---|
| `1 / 2` 想得到 0.5 | 得到 **0** | `1.0 / 2` |
| `float f = 1/2;` 以为 float 能救 | 右边**先算成 0** 了 | 把浮点写进**表达式里** |
| 大数相乘直接赋给 `long long` | 中间结果**先溢出**，得到 0 | `(long long)a * b` |
| 以为 `long long` 会自动保护乘法 | 它只保证"存"，不保证"算" | 先转换再算 |
| 用 `%d` 打印 `long long` | 输出错 | 用 **`%lld`** |
| 以为有效数字少就是 float | 浮点字面值**默认 double** | 想要 float 加 `f` 后缀 |

## 一句话记忆

> **整数字面值默认 `int`（放不下逐级升级），浮点字面值一律 `double`。**
> **两边都是 `int`，结果一定是 `int`** → `1/2 = 0`。
> **`long long ll = a*b;` 救不了溢出**，因为乘法先算完再赋值 → 必须 `(long long)a * b`。
