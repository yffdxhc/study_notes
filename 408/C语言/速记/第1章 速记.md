## 一、IDE 与项目

- **解决方案（`.sln`）是什么？** VS 自己的"收纳盒"，一个可以装**多个**项目。与 C 语言无关，纯 IDE 概念。
- **项目是什么？它是不是编译的最小单位？** **是**——项目是一套能编译出一个程序（exe / lib）的配置，**在 IDE 里它就是编译的最小单位**（VS 里你编译的是「项目」，从来不是「解决方案」）。
- **那编译器内部以什么为单位？** 按单个 `.c` 文件（C 标准叫「翻译单元」）逐个编译，最后链接成一个产物。
  > 两个说法都对，只是**粒度不同**：IDE 粒度 = 项目；编译器粒度 = 翻译单元。
- **VS 里能用 `.cpp` 写 C 吗？** 能。**IDE 不检查你写的是 C 还是 C++**。
- **CLion 和 CMake 是什么关系？** CLion 是 **IDE**，它**使用 CMake** 做构建系统。
- **CMake 里有"解决方案"吗？** 没有。CMake 只有两层：**项目（project）+ 目标（target）**。

## 二、一份 C 程序的结构

- **程序必需哪个函数？它返回什么？** `main`，程序入口；返回 `int`，`return 0` 表示正常结束。
- **`#include` 是什么？** **预处理指令**，用来引入头文件（那里放函数声明）。
- **哪些地方不加分号？** 复合语句 `{}`、预处理指令。
- **⚠️ 哪些地方反而必须加？** **`struct` / `union` / `enum` 的定义**要加，`do { } while(cond);` 也要——漏了报错很难懂。
- **符号有什么要求？** 一律用**英文** `;` `"` `'` `()`。中文符号会报错。

## 三、调试

- **调试包含哪两步？** **编译 + 运行**。（严格说完整链路：预处理 → 编译 → 汇编 → 链接）
- **断点停在哪？** 停在**这一行执行之前**，不是执行完。`F5` 开始调试。
- **`F10` 步过是什么意思？** **不进入**函数内部，但函数**照常执行完**——不是"跳过不执行"。
- **`F11` 步入呢？** 进入函数内部，一行行看。
- **调试时能看到什么？** 变量值、`&变量`（地址）、内存窗口。
- **黑框框（控制台）是什么？** 操作系统的一个**进程**，用来接程序的输出。

## 四、易错点与习惯

- **局部变量不初始化会怎样？** 值是**不确定的**，**读它就是 UB**（未定义行为）。
- **全局变量 / `static` 变量不初始化呢？** 标准保证**自动为 0**。
  > 所以"C 里未初始化就是垃圾"**只对局部变量成立**。
- **该养成什么习惯？** **先初始化再用**，杜绝 UB。
- **C++ 是 C 的严格超集吗？** **不是**（408 按"大致超集"理解够用）：

  | 代码 | 在 C 里 | 在 C++ 里 |
  |---|---|---|
  | `int class = 1;` | ✅ | ❌ `class` 是关键字 |
  | `int *p = malloc(4);` | ✅ `void*` 隐式转换 | ❌ 必须 `(int*)malloc(4)` |
  | `void f();` | 参数不确定 | 参数无（语义不同） |

