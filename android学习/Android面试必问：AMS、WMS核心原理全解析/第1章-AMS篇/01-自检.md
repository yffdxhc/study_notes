## 一、整条链：init → zygote → system_server → App

一层 fork 一层（AMS 和 WMS 都住在 `system_server` 里）：

1. 按下电源键，上电
2. 引导芯片执行 ROM 里的固化代码（ROM ≈ 硬盘：断电不丢）
3. bootloader 被搬进 RAM 并执行（RAM ≈ 内存：断电就丢，**所以要先搬**）
4. kernel 启动（Linux；fork 下一层）
5. init，**PID=1**（用户空间鼻祖：第一个开辟用户空间的进程；fork 下一层）
6. zygote，孵化器／受精卵（Java 进程鼻祖：靠 fork 不断分裂；fork 下一层）
7. system_server（大儿子；启动 AMS/WMS/PKMS 等近百个服务）
8. App 进程（同样由 zygote fork 出来）

init 负责系统仆从（`kthreadd` 等）；zygote 负责 fork 出 Java 进程 —— **工厂与服务分开**。

## 二、四层，逐层 fork

| 层 | 谁生了谁 |
|---|---|
| **1 层** | init(PID 1) 生了 `kthreadd`（不用管）、`zygote` |
| **2 层** | zygote 生了 `system_server`、App 进程 |
| **3 层** | system_server 生了 AMS/WMS/PKMS 等近百个服务（**这些不是进程，是服务**） |
| **4 层** | App 进程跑你的 Activity |

工厂（zygote）负责 fork；服务宿主（system_server）负责装服务。两者分工。

## 三、ROM 和 RAM 的区别

| | 类比 | 断电后 |
|---|---|---|
| **ROM** | 硬盘 | **数据还在** |
| **RAM** | 内存 | **数据丢失** |

### 为什么搬到 RAM 再执行

1. **启动介质不能"就地取指"**：启动介质多是按页/块访问，CPU 没法逐条指令去寻址。只有 NOR Flash（一种非易失性存储器）才支持 XIP（execute in place）
2. **上电那刻 DRAM 还不能用**：DRAM 要先初始化（时序训练）。此时 CPU 只有很小的片上 SRAM（几十~几百 KB），实际是两段式：BootROM → SPL/Preloader 进 SRAM → SPL 初始化 DRAM → 完整 bootloader 进 DRAM
3. **执行不只是取指，还要可写的栈**：代码跑起来需要栈、堆、可写全局变量；Flash 只读，当不了栈。整段搬进 RAM 后代码和数据都在可读写空间，最简单统一

## 四、init 为什么叫"用户空间鼻祖"

init 是**第一个开辟用户空间的进程** —— 在它之前的所有进程都运行在内核态。

- **内核空间**：内核层，用于内核代码、驱动
- **用户空间**：应用层，用于执行 App 的代码

所以 init 是用户空间里的第一个进程，后面所有用户空间进程都是它的后代。

### PID 记法

| 进程 | PID | 说明 |
|---|---|---|
| **init** | **1** | 用户空间第一个进程 |
| `kthreadd` | 2 | 内核线程的父进程 |
| 内核 idle / swapper | 0 | **不是**用户进程 |

## 五、init fork 出的两个关键子进程

init fork 出的两个关键**子**进程是 `kthreadd` 和 `zygote`。

- **`kthreadd`**：内核线程的父进程，处理内核里的工作（不用管）
- **`zygote`**：孵化器／受精卵，后面所有 Java 进程的源头（**重点**）

## 六、zygote 为什么叫"受精卵／孵化器"

受精卵就是一个单细胞不断分裂，zygote 也是靠 `fork()` 不断分裂出进程。

它 fork 出两个关键东西：

- **`system_server`** —— 第一个分裂出来的进程 → 所以叫"**大儿子**"
- **App 进程** —— 所有应用进程也由 zygote fork 出来

它是「Java 进程的鼻祖」：首次进入 Java 世界的进程。它先把自己变成"能跑 Java 的进程"（虚拟机 + 预加载类），之后的 Java 进程都由它 fork —— **子进程天生就是 Java 进程，不用再初始化一遍**。

## 七、system_server 为什么叫"大儿子"

zygote 第一个分裂出来的进程 → 所以叫"大儿子"。

**它装了什么**：所有 Java 系统服务，都是在 `system_server` 这个进程里启动的。例如：

| 服务 | 管什么 |
|---|---|
| **AMS** | Activity 管理 |
| **WMS** | 窗口管理 |
| **PKMS**（`PackageManagerService`） | 包管理 |

所以 system_server 挂了 = 系统服务全挂 = **系统重启**（Watchdog 会处理）。

## 八、zygote 为什么被称为"Java 进程的鼻祖"

zygote 是**首次进入 Java 世界的进程**。它先把自己变成"能跑 Java 的进程"（虚拟机 + 预加载类），之后的 Java 进程都由它 fork —— 子进程天生就是 Java 进程，不用再初始化一遍。
