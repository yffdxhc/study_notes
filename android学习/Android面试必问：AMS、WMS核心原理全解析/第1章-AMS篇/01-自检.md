init → zygote → system_server → App 这条链：
Android启动链路:一层fork一层(AMS和WMS都住在system_server里)：
1、按下电源键，上电
2、引导芯片执行ROM里的固化代码(ROM 约等于 硬盘:断电不丢)
3、bootloader被搬进RAM并执行(RAM 约等于 内存:断电就丢，所以要先搬)
4、kernel启动(Linux；fork下一层)
5、init PIS=1(用户空间鼻祖:第一个开辟用户空间的进程；fork下一层)
6、zygote 孵化器/受精卵(java进程鼻祖:靠fork不断分裂；fork下一层)
7、system_server(大儿子；启动AMS/WMS/PKMS等近百个服务)；8、App进程(同样由 zygote fork 出来)
init 负责系统仆从(kthreadd等)；zygote 负责 fork 出 java进程——工厂与服务分开

四层，逐层fork:
1层 int(PID 1) 生了 kthreadd(不用管)、zygote
2层 zygote 生了 system_server、App进程
3层 system_server 生了 AMS/WMS/PKMS等近百个服务(这些不是进程，是服务)
4层 App进程 跑你的Activity
工厂(zygote)负责fork;服务宿主(system_server)复制装服务。两者分工

------

ROM 和 RAM 的区别：
ROM(类比硬盘)    断电后数据还在
RAM(类比内存)    断电后数据丢失

为什么搬到RAM再执行：
1、启动介质不能"就地取指"。启动介质多是按页/块访问，CPU 没法逐条指令去寻址。只有 NOR Flash(一种非易失性存储器) 才支持 XIP（execute in place）
2、上电那刻DRAM还不能用。DRAM 要先初始化（时序训练）。此时 CPU 只有很小的片上 SRAM（几十~几百 KB），实际是两段式：BootROM → SPL/Preloader 进 SRAM → SPL 初始化 DRAM → 完整 bootloader 进 DRAM
3、执行不只是取指，还要可写的栈。代码跑起来需要栈、堆、可写全局变量；Flash 只读，当不了栈。整段搬进 RAM 后代码和数据都在可读写空间，最简单统一

------

init 为什么叫"用户空间鼻祖"：
init 是第一个开辟用户空间的进程 —— 在它之前的所有进程都运行在内核态。
内核空间是内核层，用于内核代码、驱动
用户空间是应用层，用于执行App的代码
所以 init 是用户空间里的第一个进程，后面所有用户空间进程都是它的后代。

init进程的PID=1,是用户空间的第一个进程
kthreadd的PID=2,是内核线程的父进程
内核的idle/swapper进程的PID=0,不是用户进程

------

init fork 出的两个关键子进程：
init fork出的两个关键自进程是kthreadd和zygote。
kthreadd是内核线程的父进程，处理内核里的工作(不用管)
zygote是孵化器 / 受精卵，后面所有 Java 进程的源头(重点)

------

zygote 为什么叫"受精卵/孵化器:
受精卵就是一个单细胞不断分裂， zygote 也是靠 fork() 不断分裂出进程。
它 fork 出两个关键东西，system_server    第一个分裂出来的进程 → 所以叫"大儿子"；App 进程    所有应用进程也由 zygote fork 出来
它是「Java 进程的鼻祖」，是首次进入 Java 世界的进程。它先把自己变成"能跑 Java 的进程"（虚拟机 + 预加载类），之后的 Java 进程都由它 fork —— 子进程天生就是 Java 进程，不用再初始化一遍。

------

system_server 为什么叫"大儿子"：
zygote第一个分裂出来的进程 → 所以叫"大儿子"

它装了什么：所有 Java 系统服务，都是在 system_server 这个进程里启动的
例如：AMS管Activity 管理；WMS管窗口管理；PKMS管理包管理
所以 system_server 挂了 = 系统服务全挂 = 系统重启（Watchdog 会处理）。

------

zygote 为什么被称为"Java 进程的鼻祖"：
zygote 是首次进入 Java 世界的进程。它先把自己变成"能跑 Java 的进程"（虚拟机 + 预加载类），之后的 Java 进程都由它 fork —— 子进程天生就是 Java 进程，不用再初始化一遍。
