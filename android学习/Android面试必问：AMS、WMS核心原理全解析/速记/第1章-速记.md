## 一、整体启动链路

- **按下电源键后最先执行什么？** 引导芯片执行 **[ROM](../00-术语表.md#rom) 里固化**的那段代码。
- **引导代码把什么搬到哪？** 把 **bootloader 从 ROM 搬到 [RAM](../00-术语表.md#ram)**，再执行。
- **ROM 和 RAM 什么区别？** ROM ≈ 硬盘（**断电不丢**）；RAM ≈ 内存（**断电丢失**）。
- **内核启动的第一个进程是谁？** **`init`，PID = 1**。
- **为什么 `init` 叫"用户空间鼻祖"？** 它是**第一个开辟用户空间的进程**，之前都在内核态。
- **用户空间 vs 内核空间？** 用户空间跑 App 代码（应用层）；内核空间是内核层。
- **`init` fork 出哪两个关键进程？** `kthreadd`（内核线程，不用管）+ **`zygote`**。
- **`zygote` 为什么叫孵化器/受精卵？** 它靠 **`fork()` 不断分裂**出进程，像受精卵分裂。
- **`zygote` 的"大儿子"是谁？** **`system_server`** —— 第一个被 fork 出来的进程。
- **为什么说 `zygote` 是 Java 进程鼻祖？** 它是**第一个跨过 JNI 桥进入 Java 层**的进程。
- **AMS 和 WMS 住在哪？** 都在 **`system_server`** 进程里。

## 二、zygote 启动流程

- **进程和虚拟机，谁包含谁？** **一个进程里包一个虚拟机**，进程概念更大。
- **为什么"一进程一虚拟机"？** 进程是**资源分配的最小单位**（内存私有）→ 虚拟机主要**管内存** → 一对一最好管；也符合**沙盒机制**（一个进程挂了不影响别人）。
- **`runtime.start()` 干三件事？** ① **创建虚拟机** ② **注册 JNI** ③ **进入 Java 层**。
- **为什么进 Java 层必须靠 JNI？** 之前都在内核/native 层，要有**入口**（`ZygoteInit.main`）+ **桥**（JNI）。
- **`ZygoteInit.main()` 干四件事？** ① 预加载 ② 建 socket ③ **fork `system_server`** ④ 死循环等消息。
- **预加载的真实作用是什么？** **加快应用进程启动**（不是省内存！）。
- **为什么不能说"省内存"？** fork 是**写时拷贝**，不修改就不复制；要说省内存必须把这层讲清。
- **为什么用 socket 而不用 [Binder](../00-术语表.md#binder)？** ① Binder 还没初始化好 ② **Binder 是多线程机制，fork 容易死锁**（锁在子进程里解不开）。
- **为什么不让 `init` 来 fork 应用进程？** `init` 还要创建很多东西，**应用进程不需要那些**；且此时虚拟机还没建。
- **为什么不让 `system_server` 来 fork？** 它要启动**近百个系统服务**，这些服务**全系统公用一份**，没必要和应用同进程。

## 三、system_server 的创建

- **fork 之后父子进程怎么区分？** 看 **`fork()` 的返回值**。
- **返回值规则？** **父进程 = 子进程的 PID**（>0）；**子进程 = 0**（0 是无效值，只为区分）。
- **为什么必须能区分？** fork 出来的代码**一模一样**，但两者任务不同（一个等消息、一个启服务）。
- **子进程接下来做什么？** `r.run()` 里**反射**调 `SystemServer.main()`。
- **父进程接下来做什么？** 回到 **`runSelectLoop` 死循环**等 AMS 来"要进程"。
- **`pid == 0` 和 `r != null` 什么关系？** **同一件事的两种判断**（`r` 只在子进程里创建）。
- **`system_server` 和 `SystemServer` 什么关系？** 一个是**进程名**（小写）、一个是**类名**（驼峰），**同一个东西**。

## 四、ATM 和 AMS 的启动

- **`system_server` 启动服务的四步？** 创建 `SystemServiceManager` → **引导服务** → **核心服务** → **其他服务** → 进 `Looper.loop()`。
- **AMS 在哪类服务里启动？WMS 呢？** **AMS 在引导服务**（早）；**WMS 在其他服务**（晚）。
- **为什么这么排？** 看**依赖关系** —— WMS 启动后**立刻要和 AMS 关联**。
- **Android 10 有什么变化？** AMS **拆出 [ATM](../00-术语表.md#ams-atm)**（`ActivityTaskManagerService`）：ATM 管任务/Activity，AMS 管进程等。
- **`startService` 干两件事？** ① **反射创建服务对象** ② 调 **`Lifecycle.onStart()`**。
- **读源码时看到传 `Class` / 全类名，说明什么？** 基本就是**反射**。
- **ATM 创建时的核心对象？** **`ActivityTaskSupervisor`**（栈/任务管理）。
- **AMS 创建时的核心对象？** 也是 **`ActivityTaskSupervisor`**。
- **AMS 在哪把自己注册进去？** `setSystemProcess()` 里 `ServiceManager.addService`。
- **AMS 同时注册的三个 Binder 服务？** **`meminfo`** / `gfxinfo` / `dbinfo`（`dumpsys` 用）。
- **`ServiceManager` 和 `SystemServiceManager` 的区别？** 前者是系统服务**大管家**（注册/查找）；后者管 **`SystemService` 的生命周期**。

## 五、Activity 启动流程（面试 6 步）

- **面试版 6 步？** ① 统一走到 `Activity.startActivity` ② → `Instrumentation.execStartActivity` ③ **跨进程**进 AMS/ATM ④ 判断目标进程**是否存在** ⑤ 不存在就 **socket 通知 zygote fork** ⑥ 应用 **`attachApplication`** 交 `ApplicationThread`
- **Android 9 前后有什么不同？** 9 及之前**进 AMS**；9 之后**进 ATM**。
- **跨进程前怎么拿到 AMS/ATM？** 通过 **`ServiceManager`**，用的是**代理模式**。
- **进程不存在时怎么创建进程？** AMS **用 socket 通知 zygote** fork；新进程再**反射**跑 `ActivityThread.main()`。
- **AMS 怎么管到新进程的生命周期？** 靠应用**主动"上户口"**：`attachApplication` 把 `ApplicationThread`（Binder）交给 AMS。
- **两个 Binder 方向分别是什么？** 应用→AMS 用 **`IActivityManager`**；AMS→应用用 **`IApplicationThread`**。

## 六、生命周期与栈

- **生命周期管理三件套？** `ClientLifecycleManager` → `ClientTransaction` → `ClientTransactionItem`。
- **哪个 item 触发 `onCreate`？** **`LaunchActivityItem`**。
- **哪个触发 `onStart` / `onResume`？** **`ResumeActivityItem`**（用状态机循环一次走完两者）。
- **谁来执行事务？** **`TransactionExecutor`**：`executeCallBack`（走 item）+ `executeLifecycleState`（走状态）。
- **Android 9 起这块有什么改动？** [Handler](../00-术语表.md#handler) 流程用**状态模式**重写。
- **栈的三层结构？** `ActivityStack` → **`Task`** → **`ActivityRecord`**。
- **`ActivityRecord` 是什么？** **一个 Activity 在 AMS 里的记录对象**（一个对应一个）。
- **Android 11 里有什么改名？** **`TaskRecord` → `Task`**。
- **怎么"看见"栈？** `dumpsys activity`。
- **栈信息能解决什么问题？** 栈溢出、明明在后台却被拉起、页面栈错乱。
- **插件化依赖哪些知识？** **AMS 启动流程** + 包管理 + 类加载 + 资源加载。
