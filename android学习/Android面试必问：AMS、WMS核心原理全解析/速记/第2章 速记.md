## 一、Window 是什么时候有的

- **Activity 和 Window 什么时候建立联系？** 在 **`attach()`** 里 —— `new PhoneWindow()` + `setWindowManager()`，**比 `onCreate` 还早**。
- **为什么随时能 `getWindow()`？** 因为 `attach` 阶段就创建好了，是公共字段。
- **`setContentView` 到底做了什么？** **只解析 XML，生成视图树**（本质是一次序列化动作）。
- **`setContentView` 把 View 挂到 Window 上了吗？** **没有！** 解析出来的 View 和 Window 之间**没有任何关联**。
- **Window 和 View 什么时候才真正连上？** **`onResume` 的 `handleResumeActivity`** 里：`makeVisible()` → **`wm.addView(decor, l)`**。
- **为什么必须等 `onResume`？** 到那时布局才建好、资源主题才就绪，窗口才有资格交给系统。
- **`wm.addView` 的三级委托是什么？** `WindowManagerImpl` →→ **`WindowManagerGlobal`（进程内唯一）** →→ `new ViewRootImpl()` → `setView()`。
- **哪个类才是真正干 UI 活的？** **`ViewRootImpl`**。
- **Activity 自己有 UI 能力吗？** **没有**，它只负责生命周期调度。
- **`Window` 自己干活吗？** 几乎不干，它只是个壳；`WindowManager` 是桥。

## 二、ViewRootImpl 怎么连到 WMS

- **`setView` 之后触发什么？** `requestLayout()` → `scheduleTraversals()` → `performTraversals()`。
- **怎么跨到 WMS？** `relayoutWindow()` → **`mWindowSession.relayout(...)`（Binder）** → `Session` → WMS。
- **`mWindowSession` 是什么？** **`IWindowSession` 的 Binder 代理**（老师强调"它就是个 Binder"）。
- **WMS 里代表一个窗口的对象是什么？** **`WindowState`**。
- **WMS 之后把活交给谁？** **`SurfaceFlinger`** 合成。
- **`token` 是什么？** **它本身是 Binder**，用来标识"这个窗口是谁的"。
- **为什么说 `ViewRootImpl` 是桥？** 上层都在应用进程内，**真正跨到系统服务的那一刀切在它**。

## 三、onResume 里能量宽高吗

- **第一次在 `onResume` 里取宽高得到几？** **0**。
- **为什么是 0？** `onResume` 回调时，**`WindowManager` 还没和 `DecorView` 绑定**；绑定发生在它返回**之后**的 `makeVisible()`。
- **从别的页面返回时有值吗？** **有**，因为之前已经完整量过一次。
- **所以准确答案是？** **不确定** —— 不是简单的"不能"。
- **度量在绘制流程里是什么地位？** **只是其中一小步**（measure → layout → draw 之一）。
- **正确取宽高的时机有哪些？** `view.post` / `doOnLayout` / `OnGlobalLayoutListener` / `onWindowFocusChanged`。
- **为什么 `onMeasure` 里 `getWidth()` 时有时无？** 同一个根因：取决于**走到遍历的哪一步**。

## 四、子线程能更新 UI 吗

- **`onResume` 之后子线程 `setText` 会怎样？** **必崩**。
- **崩在哪一行？** **`ViewRootImpl.checkThread()`**。
- **完整链路？** `setText` → `invalidate` → `ViewGroup.invalidateChild` → `invalidateChildInParent`（一路上传）→ **`ViewRootImpl.checkThread()`**。
- **`onCreate` 里子线程 `setText` 为什么不崩？** 那时 **`ViewRootImpl` 还没创建**，链条在中间就断了，`checkThread` 根本没执行。
- **不崩等于生效吗？** **不等于** —— `setText` 只是把内容**存进字段**，没触发重绘，界面不变。
- **那什么时候会显示？** 等后面真正遍历时，把字段里的内容画出来。
- **`SurfaceView` 为什么能在子线程画？** 它走 **`Surface`** 那条路，**不经过这个检查链**。

## 五、Handler 与消息屏障

- **App 为什么不会自己退出？** `ActivityThread.main()` 里 **`Looper.loop()` 是死循环**，main 永不返回。
- **Handler 的真正身份？** **App 的心脏**（"只是线程通信"是错的）。
- **"一切都是消息"包含哪些？** **生命周期、点击、UI 刷新、Fragment 生命周期**。
- **消息怎么排队？** 进 **`MessageQueue`**，**队头先执行、队尾后执行**。
- **消息屏障（sync barrier）是什么？** 挡住**同步消息**，**只放行异步消息**。
- **谁在用消息屏障？** **UI 刷新（traversal）** —— 保证刷新不被插队，**保障 16.7ms 的刷新节奏**。
- **`onResume` 里 `handler.post` 能拿到宽高吗？** **不能（0）** —— 可能排在遍历之前。
- **`postDelayed` 呢？** **能** —— 延迟够长，等遍历执行完。
- **`view.post` 为什么能？** View **内部有自己的队列**，attach 时把消息**合并**进主线程消息流，先后关系天然正确。
- **怎么用这套机制做性能监控？** 给主线程 Looper 设 **`setMessageLogging(Printer)`**，用每条消息"开始/结束"的**时间差**算耗时，筛出 Activity 生命周期那几条。
- **哪个框架这么干的？** **腾讯 Matrix**（Android 性能监控框架）。

## 六、绘制用的是同一个 Canvas 吗

- **用的是同一个 Canvas 吗？** **是**（**同一个窗口内**）。
- **Canvas 从哪来？** **`Surface.lockCanvas(dirty)`**。
- **怎么证明是同一个？** **`dispatchDraw(canvas)`** 把**同一个对象引用**一路传给子 View，全程没有新建 `Canvas`。
- **绘制的三步顺序？** **① `drawBackground`（先画背景）→ ② `onDraw` → ③ `dispatchDraw`（分发给孩子）**。
- **`FrameLayout` 有 `onDraw` 吗？** **没有**（只有 `onMeasure`/`onLayout`），但它**有背景** —— 这就是数据没加载时看到的空白界面。
- **"同一个 Canvas"带来哪两个配对要求？** **`save()`/`restore()`** 必须配对；**`lockCanvas()`/`unlockCanvasAndPost()`** 必须配对。
- **"整个 App 只有一个 Surface"对吗？** **不对** —— **每个窗口一个 Surface**，同一个窗口内共享一个 Canvas。
