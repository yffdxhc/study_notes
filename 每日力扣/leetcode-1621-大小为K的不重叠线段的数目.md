# 1621. 大小为 K 的不重叠线段的数目

> 题目：
> 
> 给你一维空间的 `n` 个点，其中第 `i` 个点（编号从 `0` 到 `n-1`）位于 `x = i` 处，请你找到 **恰好 `k` 个不重叠** 线段且每个线段至少覆盖两个点的方案数。线段的两个端点必须都是 **整数坐标**。这 `k` 个线段不需要全部覆盖全部 `n` 个点，且它们的端点 **可以** 重合。
>
> 请你返回 `k` 个不重叠线段的方案数。由于答案可能很大，请将结果对 `10^9 + 7` 取余后返回。
>
> 示例 1：`n = 4`, `k = 2` → 输出 `5`
> 5 种方案：`{(0,2),(2,3)}`、`{(0,1),(1,3)}`、`{(0,1),(2,3)}`、`{(1,2),(2,3)}`、`{(0,1),(1,2)}`
>
> 示例 2：`n = 3`, `k = 1` → 输出 `3`
> 示例 3：`n = 30`, `k = 7` → 输出 `796297179`
> 示例 4：`n = 5`, `k = 3` → 输出 `7`
> 示例 5：`n = 3`, `k = 2` → 输出 `1`
>
> 提示：`2 <= n <= 1000`；`1 <= k <= n-1`

> 📖 **阅读顺序说明**：这份文档按"从零开始"来写——
> 第一章先弄懂三个关键点，尤其是"**端点可以重合**"这句话；
> 第二章用人脑手算示例，发现"总是看最后一个点用不用"的规律；
> 第三章给出核心 DP；第四章把它优化到 `O(nk)`；
> 第五、六章是代码与走查；第七章回答疑问；
> 第八、九章是复杂度和易错点。
> 附录里还给了一个**闭式解**，可以用来验算。
>
> 如果你时间紧，直接跳到 **第三章** 看 DP，再抄 **第五章** 的三项递推代码。

## 一、先把题目读懂（三个关键点）

### 1.1 点的位置

`n` 个点排在一条线上，坐标是 `0, 1, 2, …, n-1`。

一条**线段**就是一对整数端点 `(a, b)`，其中 `a < b`，它覆盖 `a` 到 `b` 之间的所有点。

### 1.2 "每个线段至少覆盖两个点"

意味着线段的两个端点**不能是同一个点**，也就是 `a < b`（长度至少为 1）。

> 所以 `(2,2)` 这种"退化线段"是不允许的。

### 1.3 ⭐ "端点可以重合"——本题最容易被忽略的一句话

题目原文：

> 这 k 个线段不需要全部覆盖全部 n 个点，且它们的端点 **可以** 重合。

"不重叠"在这里的意思是 **内部不能交叉**，但**可以首尾相接**：

```
✅ 合法：[0,1] 和 [1,2]      ← 共用端点 1
✅ 合法：[0,2] 和 [2,3]      ← 共用端点 2
✅ 合法：[0,1] 和 [2,3]      ← 中间还有空隙
❌ 非法：[0,2] 和 [1,3]      ← 内部交叉
❌ 非法：[0,2] 和 [2,3] 吗？  ← 合法！共用的只是端点
```

看示例 1 给出的 5 种方案就明白了——其中 4 种都是"共用端点"的：

```
{(0,2),(2,3)}  ← 共用点 2
{(0,1),(1,3)}  ← 共用点 1
{(0,1),(2,3)}  ← 有间隙
{(1,2),(2,3)}  ← 共用点 2
{(0,1),(1,2)}  ← 共用点 1
```

> ⚠️ 如果把"不重叠"理解成**端点也不能碰**，答案会算少（示例 1 会得到 3 而不是 5）。这是本题第一大坑。

### 1.4 是"恰好 k 条"，不是"至多 k 条"

状态里必须带"恰好"的语义，不能混入"至多"。

### 1.5 数据规模说明

`n ≤ 1000`、`k ≤ n-1`，意味着：

- `O(nk) = 10⁶` 的算法非常轻松；
- 但 `O(n²k) = 10⁹` 就太慢了，**必须把转移里的那个求和优化掉**。

## 二、人脑会怎么算？

### 2.1 先看最小的例子：`n = 3, k = 1`

3 个点 `0, 1, 2`，选 1 条线段，任意两个不同点都可以：

```
(0,1)、(0,2)、(1,2)   →  3 种
```

正好是 `C(3, 2) = 3` ✅

### 2.2 再看 `n = 3, k = 2`

3 个点里塞 2 条线段，每条至少占 2 个点，总"点数占用"至少 4 > 3，看起来不可能……但因为**端点可以重合**：

```
(0,1) 和 (1,2)   ← 共用点 1，总共只占 3 个点
```

所以答案是 **1** ✅（示例 5）

> 这就是"端点可以重合"带来的效果：`k` 条线段最多可以只占 `k+1` 个点。

### 2.3 手算示例 1：`n = 4, k = 2`

4 个点 `0,1,2,3`，选出 2 条不重叠线段。按"第一条线段的右端点在哪儿"来列举：

| 第一条 | 第二条可以是什么 | 说明 |
|---|---|---|
| `(0,1)` | `(1,2)`、`(1,3)`、`(2,3)` | 可以和 1 相接，也可以从 2 开始 |
| `(0,2)` | `(2,3)` | 和 2 相接 |
| `(0,3)` | 无 | 没有空间了 |
| `(1,2)` | `(2,3)` | 和 2 相接 |
| `(1,3)` | 无 | 没空间 |
| `(2,3)` | 无 | 没空间 |

合计 3 + 1 + 1 = **5** ✅（示例 1）

### 2.4 从手算里发现的规律

手算时，我其实一直在问同一个问题：

> **最右边那个点，被用到了吗？如果被用到了，它是一条线段的右端点吗？**

这就是第三章 DP 的分类依据。

## 三、核心 DP

### 3.1 状态定义

设 `dp[i][j]` = **只用前 `i` 个点**（也就是 `0, 1, …, i-1`），**恰好**选出 `j` 条线段的方案数。

> 为什么按"前 i 个点"而不是"第 i 个点"来定义？因为这样能自然地用前缀答案拼出更大的答案。

### 3.2 转移：看第 `i-1` 个点（最右边的点）用不用

**情况一：点 `i-1` 不属于任何线段**

那整个方案只用了前 `i-1` 个点：

```
dp[i][j] += dp[i-1][j]
```

**情况二：点 `i-1` 是某条线段的右端点**

设这条线段是 `[s, i-1]`，其中起点 `0 ≤ s ≤ i-2`（保证 `s < i-1`，长度至少 1）。

**关键**：因为**端点可以重合**，前面那 `j-1` 条线段**可以一直用到点 `s`**。所以它们只需要全部落在前 `s+1` 个点里：

```
dp[i][j] += dp[s+1][j-1]
```

把所有可能的起点 `s` 加起来。令 `t = s + 1`，则 `t` 从 `1` 到 `i-1`：

```
dp[i][j] = dp[i-1][j] + Σ(t = 1 → i-1) dp[t][j-1]
```

> 💡 如果"端点不能重合"，求和就该是 `Σ(t = 0 → i-2)`（前一条必须结束在 `s-1` 之前）。**差的就是这一项**，也是本题最大的坑。

### 3.3 边界

| 边界 | 值 | 含义 |
|---|---|---|
| `dp[i][0]` | `1` | 一条都不选，永远是 1 种方案 |
| `dp[0][j]`（j≥1） | `0` | 0 个点凑不出线段 |
| `dp[1][j]`（j≥1） | `0` | 1 个点凑不出线段（每条至少要 2 个点） |

答案是 `dp[n][k]`。

### 3.4 汇总

```
dp[i][j] = dp[i-1][j] + Σ(t = 1 → i-1) dp[t][j-1]
```

## 四、把 `O(n²k)` 优化到 `O(nk)`

### 4.1 方法 A：前缀和

转移里的 `Σ(t = 1 → i-1) dp[t][j-1]` 是一个**前缀和**。记：

```
pre[i][j] = Σ(t = 0 → i) dp[t][j]
```

那么：

```
Σ(t = 1 → i-1) dp[t][j-1] = pre[i-1][j-1] − dp[0][j-1]
```

（`dp[0][j-1]` 在 `j-1 = 0` 时是 1，否则是 0——因为 `dp[0][0] = 1`。）

这样每格只要 `O(1)`，总复杂度降到 `O(nk)`。

### 4.2 方法 B：化简成三项递推（最优雅，推荐）

把 `dp[i][j]` 和 `dp[i-1][j]` 的表达式相减，可以**直接把求和消掉**。

**推导**（对 `i ≥ 3`）：

根据转移方程：

```
dp[i][j]   = dp[i-1][j] + Σ(t = 1 → i-1) dp[t][j-1]     …… ①
dp[i-1][j] = dp[i-2][j] + Σ(t = 1 → i-2) dp[t][j-1]     …… ②
```

① − ②（两个求和几乎一样，只差 `t = i-1` 那一项）：

```
dp[i][j] − dp[i-1][j] = dp[i-1][j] − dp[i-2][j] + dp[i-1][j-1]
```

移项得到：

```
dp[i][j] = 2 × dp[i-1][j] − dp[i-2][j] + dp[i-1][j-1]
```

**只有加加减减，没有求和**，代码极短，`O(nk)` 时间、`O(nk)` 空间（还能压到 `O(k)`）。

> 实测：这个递推在 `n=2..30`、`k=1..7` 的全部组合上，都与原始求和版本一致。

## 五、完整代码

### Java（推荐：三项递推）

```java
class Solution {
    public int numberOfSets(int n, int k) {
        final int MOD = 1_000_000_007;
        long[][] dp = new long[n + 1][k + 1];

        for (int i = 0; i <= n; i++) dp[i][0] = 1;   // 0 条线段：1 种方案

        for (int i = 2; i <= n; i++) {               // i = 1 时点不够，dp[1][j] 保持 0
            for (int j = 1; j <= Math.min(k, i - 1); j++) {   // i 个点最多选 i-1 条
                long v = (2 * dp[i - 1][j] - dp[i - 2][j] + dp[i - 1][j - 1]) % MOD;
                dp[i][j] = (v + MOD) % MOD;          // 有减法，防负数
            }
        }
        return (int) dp[n][k];
    }
}
```

### Java（前缀和版，更贴近第三章的原始推导）

```java
class Solution {
    public int numberOfSets(int n, int k) {
        final int MOD = 1_000_000_007;
        long[][] dp  = new long[n + 1][k + 1];
        long[][] pre = new long[n + 1][k + 1];       // pre[i][j] = Σ(t=0..i) dp[t][j]

        for (int i = 0; i <= n; i++) dp[i][0] = 1;
        for (int j = 0; j <= k; j++) pre[0][j] = dp[0][j];

        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= k; j++) {
                if (i >= 2) {
                    long sum = (pre[i - 1][j - 1] - dp[0][j - 1] + MOD) % MOD;
                    dp[i][j] = (dp[i - 1][j] + sum) % MOD;
                }
            }
            for (int j = 0; j <= k; j++) {
                pre[i][j] = (pre[i - 1][j] + dp[i][j]) % MOD;
            }
        }
        return (int) dp[n][k];
    }
}
```

### Python

```python
class Solution:
    def numberOfSets(self, n: int, k: int) -> int:
        MOD = 10**9 + 7
        dp = [[0] * (k + 1) for _ in range(n + 1)]
        for i in range(n + 1):
            dp[i][0] = 1

        for i in range(2, n + 1):
            for j in range(1, min(k, i - 1) + 1):
                dp[i][j] = (2 * dp[i - 1][j] - dp[i - 2][j] + dp[i - 1][j - 1]) % MOD
        return dp[n][k]
```

> Python 的 `%` 结果恒为非负，所以不用担心负数问题；Java 必须 `+ MOD`。

## 六、拿示例走一遍代码

示例 1：`n = 4, k = 2`，递推式 `dp[i][j] = 2·dp[i-1][j] − dp[i-2][j] + dp[i-1][j-1]`。

**`j = 1` 这一列：**

| i | 计算 | dp[i][1] | 含义 |
|---|---|---|---|
| 0 | — | 0 | 0 个点 |
| 1 | — | 0 | 1 个点，凑不出 |
| 2 | `2·0 − 0 + dp[1][0]=1` | **1** | 只有 `(0,1)` |
| 3 | `2·1 − dp[1][1]=0 + dp[2][0]=1` | **3** | `(0,1)(0,2)(1,2)` ← 对应示例 2 |
| 4 | `2·3 − dp[2][1]=1 + dp[3][0]=1` | **6** | 即 `C(4,2)` |

**`j = 2` 这一列：**

| i | 计算 | dp[i][2] |
|---|---|---|
| 0,1 | — | 0 |
| 2 | `2·0 − 0 + dp[1][1]=0` | 0 |
| 3 | `2·dp[2][2]=0 − dp[1][2]=0 + dp[2][1]=1` | **1** ← 对应示例 5 |
| 4 | `2·dp[3][2]=1 − dp[2][2]=0 + dp[3][1]=3` | **5** ✅ |

`dp[4][2] = 5`，与示例 1 一致。

**完整验证结果**（实测跑过）：

```
n=4, k=2   → 5          ✅ 示例 1
n=3, k=1   → 3          ✅ 示例 2
n=30, k=7  → 796297179  ✅ 示例 3
n=5, k=3   → 7          ✅ 示例 4
n=3, k=2   → 1          ✅ 示例 5
```

## 七、常见疑问 Q&A

**Q1："端点可以重合"到底怎么体现在公式里？**
体现在求和范围：新线段是 `[s, i-1]`，前面 `j-1` 条线段可以用到点 `s`，所以是 `Σ(t = 1 → i-1) dp[t][j-1]`。如果端点不能重合，就只能用到 `s-1`，求和变成 `Σ(t = 0 → i-2)`。

**Q2：既然叫"不重叠"，为什么还能共用端点？**
题目自己对"不重叠"做了定义——只要求**没有公共的内部点**，端点允许重合。示例 1 给出的 5 种方案里，有 4 种都共用了端点，这就是最直接的证据。

**Q3：三项递推是怎么推出来的？**
把 `dp[i][j]`（①）和 `dp[i-1][j]`（②）两个式子相减，两个求和只差 `t = i-1` 一项，剩下 `dp[i-1][j-1]`，整理即得。详见 4.2。

**Q4：为什么 `j` 的上界是 `i-1`？**
`i` 个点最多放 `i-1` 条线段：`[0,1], [1,2], …, [i-2,i-1]`，全靠共用端点才塞得下。再多就没地方了。写 `j <= min(k, i-1)` 可以少算无用的格子。

**Q5：Java 里为什么必须 `+ MOD`？**
三项递推里有减法 `− dp[i-2][j]`，结果可能是负数，而 Java 的 `%` 对负数返回负值。先 `+ MOD` 再 `%` 就能修正到 `[0, MOD)`。Python 的 `%` 没有这个问题。

**Q6：空间能优化到 `O(k)` 吗？**
可以。三项递推只用到第 `i-1` 行和第 `i-2` 行，所以滚动保留两行即可，空间降到 `O(k)`。

**Q7：为什么 `dp[i][0] = 1`？**
"一条线段都不选"本身就是一种方案（空方案），无论有多少个点都一样。

## 八、复杂度分析

| 方法 | 时间复杂度 | 空间复杂度 |
|---|---|---|
| 原始求和（不优化） | `O(n²k)` ≈ `10⁹` ❌ 会超时 | `O(nk)` |
| 前缀和 | `O(nk)` | `O(nk)` |
| **三项递推** | `O(nk)` | `O(nk)`（可优化到 `O(k)`） |

`n ≤ 1000`，`k ≤ n-1` → `nk ≤ 10⁶`，非常快。

## 九、易错点清单

1. **把"端点可以重合"当成"不能重合"** ❗ 求和范围会写错，答案偏小（示例 1 会输出 3 而不是 5）；
2. **状态混入"至多 k"的语义**：本题是**恰好 k**，`dp[i][0] = 1` 是唯一的空方案基准；
3. **`i = 1` 的边界**：只有 1 个点凑不出线段（三项递推从 `i = 2` 开始天然避开）；
4. **Java 减法忘记修正负数**：`(v + MOD) % MOD`；
5. **忘记取模**：`n = 1000, k = 999` 时真实答案是天量级；
6. **`j` 上界没限制**：`j` 最多到 `i-1`，越界的格子应保持 0；
7. **不优化求和直接写三重循环**：`O(n²k) = 10⁹` 会超时（`n=1000` 时）。

## 十、举一反三

这类"**在一维线上选若干不重叠对象并计数**"的题，套路一致：

| 题目 | 相同点 | 不同点 |
|---|---|---|
| 1621 本题 | 选 k 条不重叠线段计数 | 端点可重合 |
| 1259 不相交的握手 | 圆上两两配对、连线不相交计数 | 圆形排布，Catalan 数 |
| 2400 恰好移动 k 步到达某一位置的方法数 | "**恰好 k**" 的计数 DP | 状态带步数 |
| 790 多米诺和托米诺平铺 | 一维覆盖计数 | 形状更复杂 |
| 253 会议室 II / 435 无重叠区间 | 不重叠区间 | 求最值而非方案数 |

**记住这个模式**：

> 一维线上的**计数**类问题，普遍套路是：
> **`dp[i][j]` = 前 `i` 个位置里恰好放 `j` 个对象**，转移时**分类讨论"最后一个位置用不用"**；
> 如果出现求和，用**前缀和**或**做差消项**优化掉。

## 附一：一句话总结

> `dp[i][j]` = 前 `i` 个点里恰好选 `j` 条线段的方案数。因为**端点可以重合**，新线段 `[s,i-1]` 前面可以一直用到点 `s`，于是 `dp[i][j] = dp[i-1][j] + Σ(t=1→i-1) dp[t][j-1]`；再把两个相邻式子相减，化简成 **`dp[i][j] = 2·dp[i-1][j] − dp[i-2][j] + dp[i-1][j-1]`**，`O(nk)` 搞定。

## 附二：闭式解 `C(n + k − 1, 2k)`

> 这题其实有**组合闭式解**，可以用来验算或作另解。

**推导**：把选出的 `k` 条线段按位置排好，端点满足

```
a₁ < b₁ ≤ a₂ < b₂ ≤ … ≤ a_k < b_k        （都落在 0 … n-1）
```

这里出现的 `≤`（弱不等式）来自"**端点可以重合**"。做一次换元：

```
u_i = a_i + (i − 1)
v_i = b_i + (i − 1)
```

于是：

- `a_i < b_i` → `u_i < v_i` ✅
- `b_i ≤ a_{i+1}` → `v_i < u_{i+1}` ✅

也就是说，`u₁ < v₁ < u₂ < v₂ < … < u_k < v_k` 变成了 **`2k` 个严格递增的整数**！

它们的最大值是 `b_k + (k−1) ≤ (n−1) + (k−1) = n + k − 2`，最小值是 `0`。所以这 `2k` 个数是从 `0 … n+k−2` 这 `n+k−1` 个位置里挑出来的：

```
方案数 = C(n + k − 1, 2k)
```

**验证**：

| n | k | `C(n+k−1, 2k)` | 预期 |
|---|---|---|---|
| 4 | 2 | `C(5,4) = 5` | 5 ✅ |
| 3 | 1 | `C(3,2) = 3` | 3 ✅ |
| 5 | 3 | `C(7,6) = 7` | 7 ✅ |
| 3 | 2 | `C(4,4) = 1` | 1 ✅ |
| 30 | 7 | `C(36,14) mod (10⁹+7) = 796297179` | 796297179 ✅ |

> ⚠️ 实现闭式解要做**模意义下的除法**（需要费马小定理求逆元），比 DP 麻烦。**比赛推荐写 DP**，闭式解当验算工具。

## 附三：方法论——"看最后一个元素用不用"的计数 DP 起手式

> 本题的 DP 分类非常典型，值得当作模板记下来。

**起手式**：`dp[i][j]` 表示"前 `i` 个位置里恰好放 `j` 个对象"，然后**分类讨论第 `i` 个位置**：

| 分支 | 处理方式 |
|---|---|
| 第 `i` 个位置**不用** | 直接继承 `dp[i-1][j]` |
| 第 `i` 个位置**用了** | 找出"这个对象占用了哪一段"，把问题缩小到这一段之前 |

这个套路在很多题里都出现过：

| 题 | "最后一个元素" | "用了它"之后缩小到 |
|---|---|---|
| **1621 本题** | 最右的点 | 新线段起点之前 → `dp[t][j-1]` |
| 115 不同的子序列 | `s[i-1]` | 跳过 / 匹配 → `dp[i-1][j]` 或 `dp[i-1][j-1]` |
| 2472 不重叠回文 | 以 `i-1` 结尾 | 回文起点之前 → `dp[j]+1` |
| 3414 不重叠区间 | 排序后的第 `i` 个区间 | 跳到 `nxt[i]` → `dp[nxt[i]][k-1]` |

> **遇到"选若干个对象并计数"的题，先试着写下 `dp[i][j]`，再问自己：最后一个位置用不用？**
> 这个起手式能解决相当大一部分计数 DP。
