# 115. 不同的子序列（Distinct Subsequences）

> 题目：
> 
> 给你两个字符串 `s` 和 `t`，统计并返回在 `s` 的子序列中 `t` 出现的个数。
>
> 测试用例保证结果在 32 位有符号整数范围内。

> 📖 还不熟悉动态规划？建议先跳到文末 **《附录：什么叫动态规划？怎么理解它》** 再回来看正文。

===

## 一、题面解读

**子序列**：从原字符串中删除若干字符（可以一个不删，但不能改变剩余字符的相对顺序）得到的新字符串。
例如 `s = "rabbbit"`，它有很多子序列，其中等于 `t = "rabbit"` 的共有 3 种。

题目要我们数的是 **方案数**——不是判断 "能不能"，而是要数出 "有几种方式" 能从 `s` 里挑出等于 `t` 的子序列。

## 二、思路：动态规划

这是一道典型的 **子序列匹配计数** 题目，本质上是 **LCS（最长公共子序列）思想的计数版**。

核心思路是：一个一个字符地处理 `s`，考察它能如何一步步拼出 `t`。因为一个子序列匹配要么用当前字符，要么不用（跳过），所以可以拆成两个子问题。

### 定义状态

设 `dp[i][j]` 表示 **用 `s` 的前 `i` 个字符，能凑出 `t` 的前 `j` 个字符的子序列个数**。

- `i` 从 0 到 `len(s)`
- `j` 从 0 到 `len(t)`

### 转移方程

当我们处理到 `s[i-1]`（`s` 的第 `i` 个字符）和 `t[j-1]`（`t` 的第 `j` 个字符）时，分两种情况：

**情况一：`s[i-1] != t[j-1]`**

这个字符用不上，只能 **跳过** 它，方案数和 "用 `s` 前 `i-1` 个字符凑 `t` 前 `j` 个字符" 一样：

```
dp[i][j] = dp[i-1][j]
```

**情况二：`s[i-1] == t[j-1]`**

这时有 **两条路**：

1. **跳过** 这个字符，方案数是 `dp[i-1][j]`
2. **用它匹配** `t[j-1]`，方案数是 `dp[i-1][j-1]`（`s` 前 `i-1` 个字符去凑 `t` 前 `j-1` 个字符，当前字符刚好补上第 `j` 个）

两种都算，所以相加：

```
dp[i][j] = dp[i-1][j] + dp[i-1][j-1]
```

> 一句话记忆：**字符相等时，等于「跳过」加上「匹配」；不相等时，只能「跳过」。**

### 初始状态（边界）

- `dp[i][0] = 1`：`t` 为空串时，任何 `s` 前缀都只有 **1 种** 办法（一个字符都不选），所以是 1。
- `dp[0][j] = 0`（`j > 0`）：`s` 是空串时，凑不出任何非空 `t`，所以是 0。

### 答案

```
dp[len(s)][len(t)]
```

## 三、核心理解①：公式是怎么和"一一对比"对上的？

很多人在这一步卡住：知道公式，但很难想象"拿 s、t 的字符一个一个比"的过程，到底怎么变成 `dp[i-1][j]`、`dp[i-1][j-1]` 这些加减。

**破题的窗户纸**：dp 表里 **每一个格子，恰好对应着一次具体的字符比对**。格子坐标 `(i, j)` 不是抽象符号，它就是在问：

> 我刚读到的 `s` 第 `i` 个字符，和我现在要凑的 `t` 第 `j` 个字符，长得一样吗？

下面用最经典的例子手推一遍：`s = "babgbag"`, `t = "bag"`（答案应为 5）。

### 3.1 先认清表格的"横竖"

- **横向（列）是 `t`**：目标就 3 位 `b a g`，外加一列"t 为空"（j = 0）。
- **纵向（行）是 `s`**：每多一行，代表 **"我多看了一个 s 字符"**。
- 第 `i` 行第 `j` 列的格子 = **用我看过的 `s` 前 `i` 个字符，能凑出 `t` 前 `j` 位，共有几种挑法**。

### 3.2 逐格手推整张表

先写上边界（第 0 行全是 0，第 0 列全是 1）：

| i \ j | 0（t空） | 1（b） | 2（a） | 3（g） |
|---|---|---|---|---|
| 0（空s） | 1 | 0 | 0 | 0 |
| 1（`b`） | 1 | ？ | ？ | ？ |
| 2（`ba`） | 1 | ？ | ？ | ？ |
| 3（`bab`） | 1 | ？ | ？ | ？ |
| 4（`babb`） | 1 | ？ | ？ | ？ |
| 5（`babgb`） | 1 | ？ | ？ | ？ |
| 6（`babgba`） | 1 | ？ | ？ | ？ |
| 7（`babgbag`） | 1 | ？ | ？ | ？ |

**填每一格，就是问一次"这一对字符相不相等"**：

- **第 1 行（新读到 `b`）**：
  - `j=1`：`b` vs `b` → **相等**。跳过得 `0`（上一行 j=1），用它当第 1 位得 `dp[0][0]=1` → `0 + 1 = 1`。说明"凑出一个 `b` 有 1 种挑法"。
  - `j=2`：`b` vs `a` → **不等**，只能抄正上 `dp[0][2] = 0`。`a` 还没出现，凑不出"ba"。
  - `j=3`：`b` vs `g` → 不等，抄正上 `0`。
- **第 2 行（新读到 `a`）**：`a` vs `b` 不等 → 正上 `1`；`a` vs `a` 相等 → `dp[1][2] + dp[1][1] = 0 + 1 = 1`（用这个 `a` 当第二位，前面已凑出的 `b` 恰好够当第一位）；`a` vs `g` 不等 → `0`。
- **第 3 行（新读到 `b`）**：关键在第 1 列：`b` vs `b` 相等 → `dp[2][1] + dp[2][0] = 1 + 1 = 2`。意思是：**s 里现在有两个位置可以当"bag 的 b"，各算一种**，方案数从 1 变 2。
- ……继续往下填，直到最后第 7 行（读到最后的 `g`），`j=3`：`g` vs `g` 相等 → `dp[6][3] + dp[6][2] = 1 + 4 = 5`。

完整表如下（数字都是上面这样一格一格比出来的）：

| i \ j | 0（t空） | 1（b） | 2（a） | 3（g） |
|---|---|---|---|---|
| 0（空s） | 1 | 0 | 0 | 0 |
| 1（`b`） | 1 | **1** | 0 | 0 |
| 2（`ba`） | 1 | 1 | **1** | 0 |
| 3（`bab`） | 1 | **2** | 1 | 0 |
| 4（`babb`） | 1 | **3** | 1 | 0 |
| 5（`babgb`） | 1 | 3 | 1 | **1** |
| 6（`babgba`） | 1 | 3 | **4** | 1 |
| 7（`babgbag`） | 1 | 3 | 4 | **5** |

右下角 `dp[7][3] = 5`，正是官方答案。示例 1（`rabbbit` / `rabbit`）同理可推出 3。

### 3.3 两种比对结果 = 两个分支，对应两种"人生选择"

**① 字符不相等 → 这个 s 字符只能扔掉**
比如第 2 行第 1 列：我读到 `a`，要凑 `t` 第 1 位 `b`。`a` 既不是 `b`，对凑 `b` 毫无帮助 → 只能丢弃。
丢弃后还能用的，还是之前那 1 个字符（`b`），情况和**没读到 `a` 时完全一样**。

所以这格 **直接等于正上方那一格**（`dp[i-1][j]`），因为字符被扔掉后"一切照旧"。

**② 字符相等 → 这个 s 字符有两条路**
比如第 7 行第 3 列：读到最后的 `g`，正好要凑 `t` 第 3 位 `g`。两条路：

- **用这个 `g`**：它去当 "bag 的 g"，那前面 6 个字符只需要凑出 "ba"（前 2 位）→ 方案数 = 左上格 `dp[6][2] = 4`；
- **不用这个 `g`**：扔掉它，等于只看前 6 个字符怎么凑完整的 "bag" → 方案数 = 正上格 `dp[6][3] = 1`。

两种都算，加起来：`4 + 1 = 5`。

### 3.4 用方向图记牢坐标含义

```
            j-1        j        ← 要凑的 t 前几位
    i-1   [ 左上 ]   [ 正上 ]    ← 上一行（没读到当前字符时的状态）
     i       ? ← 当前要填的格子
```

填 `(i, j)` 时：
- 字符不等 → 直接抄 **正上**（这个字符被扔掉，一切照旧）；
- 字符相等 → **正上 + 左上**（"不用它"的方案 + "用它补上第 j 位"的方案）。

**正上 = 跳过这个字符**（可用范围退回到前 i-1 个）；
**左上 = 用这个字符去当 t 第 j 位**（前面 i-1 个字符只需凑出前 j-1 位）。

> 这就是"一一对比"和公式之间的桥：每次比对只有"相等 / 不相等"两种结局，而 dp 表每一格记录的就是这一对比完之后，前面累积下来的挑法总数。

## 四、代码实现

### 1. 二维 DP（直观版）

```python
class Solution:
    def numDistinct(self, s: str, t: str) -> int:
        m, n = len(s), len(t)
        dp = [[0] * (n + 1) for _ in range(m + 1)]

        for i in range(m + 1):
            dp[i][0] = 1

        for i in range(1, m + 1):
            for j in range(1, n + 1):
                dp[i][j] = dp[i-1][j]          # 默认跳过 s[i-1]
                if s[i-1] == t[j-1]:
                    dp[i][j] += dp[i-1][j-1]   # 匹配这个字符

        return dp[m][n]
```

```java
class Solution {
    public int numDistinct(String s, String t) {
        int m = s.length(), n = t.length();
        int[][] dp = new int[m + 1][n + 1];

        for (int i = 0; i <= m; i++) dp[i][0] = 1;

        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                dp[i][j] = dp[i-1][j];
                if (s.charAt(i-1) == t.charAt(j-1)) {
                    dp[i][j] += dp[i-1][j-1];
                }
            }
        }

        return dp[m][n];
    }
}
```

### 2. 一维滚动数组（推荐，空间 O(n)）

观察转移方程，`dp[i][j]` 只用到 `dp[i-1][j]`（跳过）和 `dp[i-1][j-1]`（匹配），都来自上一行。所以可以把二维压成一维 `dp[j]`。**注意：内层循环必须从后往前遍历**，否则 `dp[j-1]` 会被本轮更新覆盖，导致 "匹配" 这一步用错值（原理见第六章）。

```python
class Solution:
    def numDistinct(self, s: str, t: str) -> int:
        m, n = len(s), len(t)
        dp = [0] * (n + 1)
        dp[0] = 1

        for i in range(m):
            for j in range(n, 0, -1):    # 从后往前
                if s[i] == t[j-1]:
                    dp[j] += dp[j-1]

        return dp[n]
```

```java
class Solution {
    public int numDistinct(String s, String t) {
        int m = s.length(), n = t.length();
        int[] dp = new int[n + 1];
        dp[0] = 1;

        for (int i = 0; i < m; i++) {
            for (int j = n; j >= 1; j--) {   // 从后往前
                if (s.charAt(i) == t.charAt(j-1)) {
                    dp[j] += dp[j-1];
                }
            }
        }

        return dp[n];
    }
}
```

## 五、核心理解②：一维滚动数组到底在"滚"什么？

一维版本看起来玄乎，其实它只是把二维表格 **"一行一行地存，读完一个 s 字符就整体更新成下一行"**，只保留最新一行。

### 5.1 一维数组 = 表格的一行在滚动

还是 `s = "babgbag"`, `t = "bag"`。一维数组初始就是表格第 0 行：

```
dp = [1, 0, 0, 0]     ← 表格第 0 行（s 一个字符都没读）
```

**每处理完 s 的第 i 个字符，dp 就恰好变成表格第 i 行**。整个程序就是让这一行在表格里"往下滚"，但从不保存旧行——因为旧行已经不会再被用到。

为什么旧行不会再被用到？因为二维公式里每个格子只依赖 **正上（上一行同列）** 和 **左上（上一行左列）** 两个值，不依赖更早的行。

### 5.2 代码里为什么看不到"跳过"分支？

关键洞察：更新之前，`dp[j]` 里装着的 **本来就是上一行第 j 列的值**，也就是"正上"、也就是"跳过这个字符"后的方案数！

所以：
- **"跳过"这一步不需要写代码** —— 不更新 `dp[j]`，它就自动保留"正上"的值；
- 代码只需要在 **字符相等** 时，把"左上"加进来：`dp[j] += dp[j-1]`。

### 5.3 为什么必须从后往前（j 从大到小）？

要加的那个 `dp[j-1]`，必须是**上一行的旧值**（表格里的"左上"）。

如果从左往右遍历，`dp[j-1]` 会先被**本行**更新掉；等算 `dp[j]` 时，拿到的是**本行的"左边"**，而不是上一行的"左上"。**行号差了一层，答案就错了。**

用一个小例子看错误长什么样：`s = "bb"`, `t = "bb"`，正确答案是 1（两个 `b` 都得用上）。二维表：

| i \ j | 0 | 1（b） | 2（b） |
|---|---|---|---|
| 0 | 1 | 0 | 0 |
| 1（`b`） | 1 | 1 | 0 |
| 2（`bb`） | 1 | 2 | **1** |

**正确：从后往前**
```
dp = [1, 0, 0]
读 s[0]='b'：
  j=2: 'b'=='b' → dp[2] = 0 + dp[1](旧 0) = 0
  j=1: 'b'=='b' → dp[1] = 0 + dp[0]        = 1
dp = [1, 1, 0]        ← 正确：等于表格第 1 行
读 s[1]='b'：
  j=2: 'b'=='b' → dp[2] = 0 + dp[1](旧 1) = 1   ← 用的是上一行的 dp[1]
  j=1: 'b'=='b' → dp[1] = 1 + dp[0]        = 2
dp = [1, 2, 1]        ← dp[2] = 1 ✓ 与二维表一致
```

**错误：从左往右**
```
dp = [1, 0, 0]
读 s[0]='b'：
  j=1: 'b'=='b' → dp[1] = 1                 ← 先更新了小下标
  j=2: 'b'=='b' → dp[2] = 0 + dp[1](已变 1) = 1   ← 错！用了"本行的左边"而非"上行的左上"
dp = [1, 1, 1]        ← 第 1 行就被算错了，正确应为 [1, 1, 0]
```

看到没：从左往右时，`j=2` 用到的 `dp[1]` 已经是 **本行刚算出的新值**，把"还没读第二个字符时凑不出 `bb`"错算成了 1。**倒序 = 保证加进来的 `dp[j-1]` 永远是上一行的旧值。**

### 5.4 回到主例子，看数组怎么"滚"

对照第五章的二维表，一维数组每一步都等于对应行（重点看第 3、5、6、7 行的跳变）：

```
dp 初始            [1, 0, 0, 0]   ← 行0（还没读字符）
读 s[0]='b' 后  →  [1, 1, 0, 0]   ← 行1：j=1 处 b 对上 b，0 + dp[0]=1
读 s[1]='a' 后  →  [1, 1, 1, 0]   ← 行2：j=2 处 a 对上 a，0 + dp[1](旧1)=1
读 s[2]='b' 后  →  [1, 2, 1, 0]   ← 行3：又一个 b，dp[1] = 1 + 1 = 2（两个 b 位置可选）
读 s[3]='b' 后  →  [1, 3, 1, 0]   ← 行4：第三个 b，dp[1] = 2 + 1 = 3
读 s[4]='g' 后  →  [1, 3, 1, 1]   ← 行5：第一个 g 对上 g，0 + dp[2](旧1)=1，首次凑出"bag"
读 s[5]='a' 后  →  [1, 3, 4, 1]   ← 行6：第二个 a，dp[2] = 1 + dp[1](旧3)=4
读 s[6]='g' 后  →  [1, 3, 4, 5]   ← 行7：第二个 g，dp[3] = 1 + dp[2](旧4)=5  ← 答案！
```

每个跳变中加上的数，都是**倒序保证没被本行污染**的上一行旧值。最终 `dp[3] = 5`，和二维表右下角一模一样。

### 5.5 两个常见小疑问

1. **为什么 `dp[0]` 永远是 1、从不更新？** 它对应表格 j = 0 那一列（t 为空串），凑空串永远只有 1 种办法（什么都不选），所以内层循环从 `j = n` 走到 1，故意不碰它。
2. **为什么代码里找不到"跳过"？** 跳过 = 抄正上 = `dp[j]` 的旧值原地不动。你什么都不写，它就已经是"跳过"的结果了；只有相等时多写一行累加。这是读懂一维代码最省力的视角。

## 六、复杂度

- **时间复杂度**：O(m · n)，其中 `m = len(s)`、`n = len(t)`
- **空间复杂度**：二维 O(m · n)，一维优化后 O(n)

## 七、易错点总结

1. **边界 `dp[i][0] = 1` 容易漏**：空子序列在任何前缀里都算 1 种。
2. **一维优化必须从后往前**：否则 "匹配" 分支用到的是本行已更新的"左边"，而不是上一行的"左上"，会算多（见 5.3 的 `bb/bb` 反例）。
3. **结果是方案数不是布尔值**：不能用简单的 `true/false` 去判断，要累加。
4. **类型范围**：题目保证结果在 32 位有符号整数内，所以用 `int` 即可；若无此保证则用 `long` 或取模。

## 八、扩展与同类题

这一类「子序列/子串出现次数」的 DP 题常用类似思路，核心都是 **当前字符「选或不选」** 的分支计数：

- **LCS（最长公共子序列）**：`dp[i][j]` 存长度而非方案数
- **编辑距离**：额外有「替换 / 插入 / 删除」三种操作
- **通配符 / 正则匹配**：同样是递推比较的思路

把这道题的转移方程理解透，这些题目就都有「套路」可循了。

## 附录：什么叫动态规划？怎么理解它

> 在啃 115 这类题之前，值得先把"动态规划"这个概念本身讲透。本文用大白话 + 最简单的例子讲，最后再回到 115 题对照，你会发现它没那么玄。

### 一、一句话定义

> **动态规划（DP）就是把一个大问题，拆成很多个相互重叠的小问题，先算出小问题的答案并记下来，再用小答案拼出大答案。**

拆开看三个关键词：

1. **拆**——大问题能拆成更小的问题（比如"凑出 bag"拆成"先凑 b、再凑 ba、再凑 bag"）；
2. **重叠**——这些小问题会被反复用到（同一个"凑 ba"的答案，后面好多地方都要用）；
3. **记住**——算过一次就存进表里，下次直接用，**绝不重算**。

### 二、最经典的例子：爬楼梯

题目：一次能上 1 级或 2 级台阶，爬 10 级台阶有几种走法？

**先想递归（暴力拆）：**
爬 10 级的走法 = 爬 9 级的走法 + 爬 8 级的走法（最后一步要么跨 1 级、要么跨 2 级）。

于是 `f(10) = f(9) + f(8)`，`f(9) = f(8) + f(7)`…… 一路拆到 `f(1) = 1`、`f(2) = 2`。
这个公式就是**状态转移方程**——但它会疯狂重复计算（`f(8)` 被算了 3 遍、`f(7)` 被算 5 遍……）。

**动态规划的改进：算过的就存下来。**
自底向上从 `f(1)`、`f(2)` 开始，逐个算并**填进一张表**：

| 台阶 n | 1 | 2 | 3 | 4 | 5 | ... | 10 |
|---|---|---|---|---|---|---|---|
| 走法 f(n) | 1 | 2 | 3 | 5 | 8 | ... | **89** |

每个新值 = 前两个值之和，一路推到 `f(10) = 89`。**这就是动态规划**：小问题答案存表 → 大问题答案查表相加 → 一次都不重算。

### 三、动态规划的三板斧

**① 定义状态** —— `dp[i]`（或 `dp[i][j]`）表示什么？
> 就是"我要在表里存什么"。比如爬楼梯：`dp[i]` = 爬到第 i 级台阶的走法数。

**② 找状态转移方程** —— `dp[i]` 怎么由更小的状态算出来？
> 比如 `dp[i] = dp[i-1] + dp[i-2]`。这一步是整个 DP 的灵魂，也是最难的一步。
> 技巧：问自己——**"最后一步"有哪些可能？** 每种可能对应一个小问题的答案，加起来就行。

**③ 定初始值（边界）** —— 最小的状态直接给答案，不靠公式。
> 比如 `dp[1] = 1`、`dp[2] = 2`。没有边界，公式就推不动。

> **伪代码套路**：建表 → 填边界 → 按转移方程从前往后填 → 返回 `dp[n]`。
> 几乎 80% 的 DP 题都是这个骨架，115 题只是从一维变二维而已。

### 四、回到 115 题对照

现在回看正文里的公式，是不是瞬间亲切了：

- **状态**：`dp[i][j]` = 用 s 前 i 个字符凑出 t 前 j 位的方案数（这就是"表里存什么"）
- **转移**：字符相等时 `dp[i][j] = dp[i-1][j] + dp[i-1][j-1]`——对应"最后这个 s 字符**要么不用、要么用**"，跟爬楼梯"最后一步跨 1 级还是 2 级"是**同一个思维方式**
- **边界**：`dp[i][0] = 1`、`dp[0][j] = 0`（最小的状态直接给值）
- **答案**：`dp[len(s)][len(t)]` = 表右下角

> 两道题的结构完全一样：**大问题怎么由"最后一步的选择"拆成小问题，是所有 DP 题统一的问法。**

### 五、怎么判断一道题该用 DP？

看到这些信号，就优先想 DP：

1. 题目问的是 **"有多少种方案 / 最大 / 最小 / 最值"**，且
2. 你能从后往前想：**"最后一步做完什么，能让问题变小？"**，且
3. 拆出来的小问题**会重复出现**。

如果拆出来的子问题互不重叠（比如分治里的快排），那就不是 DP 而是分治；如果每一步都贪心地只做当下最好的选择，那可能是贪心——**DP 的特点是"要比较所有选择，取最优或求和"**。

| 阶段 | 练手题 | 学到什么 |
|---|---|---|
| 入门 | 爬楼梯、斐波那契、打家劫舍 | 一维 dp、状态转移怎么想 |
| 进阶 | 不同路径、最大子数组和 | 二维 dp、表怎么填 |

先把爬楼梯那类入门题吃透，建立"填表"的手感，再回头看 115，你会发现它的核心思路和爬楼梯一模一样。
