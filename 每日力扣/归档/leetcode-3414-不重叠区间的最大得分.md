# 3414. 不重叠区间的最大得分

> 题目：
> 
> 给你一个二维整数数组 `intervals`，其中 `intervals[i] = [li, ri, weighti]`。区间 i 的起点为 `li`，终点为 `ri`，权重为 `weighti`。你最多可以选择 **4** 个互不重叠的区间。所选择区间的 **得分** 定义为这些区间权重的总和。
>
> 返回一个至多包含 4 个下标且 **字典序最小** 的数组，表示从 `intervals` 中选中的互不重叠且得分最大的区间。
>
> **如果两个区间没有任何重叠点，则称二者互不重叠。特别地，如果两个区间共享左边界或右边界，也认为二者重叠。**
>
> 示例 1：`intervals = [[1,3,2],[4,5,2],[1,5,5],[6,9,3],[6,7,1],[8,9,1]]` → 输出 `[2,3]`
> 示例 2：`intervals = [[5,8,1],[6,7,7],[4,7,3],[9,10,6],[7,8,2],[11,14,3],[3,5,5]]` → 输出 `[1,3,5,6]`
>
> 提示：`1 <= intervals.length <= 5 * 10^4`；`1 <= li <= ri <= 10^9`；`1 <= weighti <= 10^9`

## 一、先把题目读懂（三个关键词 + 一个陷阱）

### 1.1 什么叫"互不重叠"？——共享边界也算重叠！

题目特别强调了一句：

> 如果两个区间共享左边界或右边界，**也认为二者重叠**。

所以下面这些都是**冲突**的：

| 区间 A | 区间 B | 是否冲突 | 原因 |
|---|---|---|---|
| `[1,5]` | `[5,8]` | ❌ 冲突 | 共享点 5 |
| `[1,5]` | `[6,9]` | ✅ 相容 | 5 < 6，中间隔了空隙 |
| `[1,5]` | `[4,7]` | ❌ 冲突 | 区间 [4,5] 重叠 |
| `[1,3]` | `[4,5]` | ✅ 相容 | 3 < 4 |

**结论**：两个区间相容的条件是**严格的** `r_a < l_b`（或者对称地 `r_b < l_a`）——**不是** `≤`。

> ⚠️ 这是本题最经典的写错点：把 `<` 写成 `<=`。

### 1.2 "最多选 4 个"意味着什么？

- 是**至多** 4 个，不是恰好 4 个——可能只选 1 个、2 个，甚至一个也选不了就不选；
- 4 这个数字很小，小到可以当作 **DP 的一个维度**（`k = 0, 1, 2, 3, 4`）；
- 如果题目说"最多 n 个"，这题就完全不一样了。

### 1.3 "字典序最小的下标数组"是什么意思？

在所有**得分相同**的方案里，挑出下标数组字典序最小的那个。

> 字典序比较：从左往右逐位比，第一个不同的位置谁小谁就小；如果一个是另一个的前缀，则**短的更小**（比如 `[2]` < `[2,3]`）。

举例：
- `[2,3]` 和 `[1,5]` 比较 → 第 1 位 `2` vs `1`，所以 `[1,5]` 更小；
- `[2,3]` 和 `[2,4]` 比较 → 第 1 位相同，第 2 位 `3` vs `4`，所以 `[2,3]` 更小。

注意返回的数组是**原始下标**（不是排序后的位置），而且**天然升序**。

### 1.4 为什么不能暴力？

`n` 最多 `5 × 10⁴`。哪怕只考虑"选 4 个"的组合数，也是 `C(50000, 4) ≈ 2.6 × 10¹⁷`——天文数字。

> 所以必须用**动态规划**，把"从前 i 个区间里选 k 个"的答案复用起来。

### 1.5 题目要求（大白话版）

> 从一堆带权重的区间里，挑出**互不重叠**的若干个（**最多 4 个**），让**权重和最大**；如果有多组方案得分一样，输出**下标数组字典序最小**的那一组。

## 二、人脑会怎么算这道题？

### 2.1 先手算示例 1

```
intervals = [
  0: [1,3] w=2
  1: [4,5] w=2
  2: [1,5] w=5
  3: [6,9] w=3
  4: [6,7] w=1
  5: [8,9] w=1
]
```

我们试着找最高分的组合：

| 组合 | 是否相容 | 得分 |
|---|---|---|
| `{2, 3}` = `[1,5]` + `[6,9]` | `5 < 6` ✅ | 5+3 = **8** |
| `{0, 1}` = `[1,3]` + `[4,5]` | `3 < 4` ✅ | 2+2 = 4 |
| `{0, 3}` = `[1,3]` + `[6,9]` | `3 < 6` ✅ | 2+3 = 5 |
| `{2, 4}` = `[1,5]` + `[6,7]` | `5 < 6` ✅ | 5+1 = 6 |
| `{2, 3, 5}` | `[6,9]` 与 `[8,9]` 重叠 ❌ | — |
| `{2, 4, ...}` | `[6,7]` 和 `[8,9]`：`7 < 8` ✅ | 5+1+1 = 7 |

最高分是 **8**，只有 `{2,3}` 这一组达到，所以答案是 `[2,3]` ✅

### 2.2 手算时你其实在做"带权区间调度"

如果把"最多 4 个"这个限制拿掉，这道题就是经典的 **带权区间调度（Weighted Interval Scheduling）**：

> 在一堆带权区间里选互不重叠的若干个，使权重和最大。

经典做法的思路是：
1. 把区间**按端点排序**；
2. 对每个区间，快速找到"选了它之后，下一个能选的是谁"；
3. **DP**：每个区间要么不选，要么选了然后跳到下一个可用区间。

本题只是多加了两件事：**限制最多 4 个** + **并列时取字典序最小**。

### 2.3 发现关键性质：排序后，"能选的"是一段后缀

假设我们**按左端点从小到大排序**。那么对于第 `i` 个区间 `[l_i, r_i]`：

> 任何与它相容的区间，左端点必须 **大于** `r_i`。而在排好序的数组里，左端点是**单调递增**的，所以这些相容区间一定是**排在后面的连续一段后缀**！

这个性质极其关键，它把"哪些区间能选"变成了"从某个位置往后"——用一个 **二分** 就能定位。

## 三、从人脑到代码：为什么是"排序 + 二分 + 从后往前 DP"

### 3.1 为什么要排序？

因为要让"相容性"变成**位置关系**。排序后，左端点单调递增，"下一个可用的区间"就能用二分快速找到，不需要每次去扫描所有区间。

### 3.2 为什么要二分？

对每个区间 `i`，我们需要知道：**排序后第一个左端点 > r_i 的位置**。记作 `nxt[i]`。

因为左端点已经有序，这就是个"找第一个大于 x 的位置"的标准二分（`lower_bound` / `bisect_right` 语义）。

```
排序后：   [1,3]   [1,5]   [4,5]   [6,7]   [6,9]   [8,9]
索引:        0       1       2       3       4       5
                                      ↑
第 0 个区间 [1,3]，r=3：第一个「左端点 > 3」的是索引 2 的 [4,5] → nxt[0] = 2
```

### 3.3 为什么从后往前 DP？

因为"选了 `i` 之后"要跳到 `nxt[i]`，而 `nxt[i] > i`（一定在后面）。所以：

> 先算**后面**的状态，再算**前面**的状态 —— 用的时候一定是算好的。

这正是"从后往前"递推的原因。

## 四、思路分步拆解

### 第一步：带上原始下标排序

答案要输出**原始下标**，所以排序时必须把下标一起带着走（用一个 `int[4]` 存 `{l, r, w, 原始下标}`）。

```java
int[][] a = new int[n][4];
for (int i = 0; i < n; i++) {
    a[i] = new int[]{intervals[i][0], intervals[i][1], intervals[i][2], i};
}
Arrays.sort(a, (x, y) -> x[0] != y[0] ? Integer.compare(x[0], y[0])
                                      : Integer.compare(x[1], y[1]));
```

### 第二步：二分求 `nxt[i]`

```java
// 第一个「左端点 > a[i].r」的位置
int lo = i + 1, hi = n;
while (lo < hi) {
    int mid = (lo + hi) >>> 1;
    if (a[mid][0] > a[i][1]) hi = mid;   // 严格大于！共享边界算重叠
    else lo = mid + 1;
}
nxt[i] = lo;
```

### 第三步：设计 DP 状态（关键）

- `f[i][k]` = 从第 `i` 个区间往后、**最多再选 k 个**，能得到的**最大得分**；
- `g[i][k]` = 达成 `f[i][k]` 的**字典序最小的原始下标数组**。

> 注意"下标数组"本身也要作为状态存下来！这是本题和普通区间调度最大的不同。

### 第四步：转移方程

对状态 `(i, k)`，只有两个选择：

| 选择 | 得分 | 下标列表 |
|---|---|---|
| **不选** 区间 `i` | `f[i+1][k]` | `g[i+1][k]` |
| **选** 区间 `i` | `f[nxt[i]][k-1] + w_i` | 把 `原始下标 i` 插入 `g[nxt[i]][k-1]` |

```
f[i][k] = max( f[i+1][k] ,  f[nxt[i]][k-1] + w_i )
                        ↑                ↑
                     不选 i          选 i，然后跳到下一个可用位置
```

**并列时的取舍**：如果两个选择的得分相同，就比**下标数组的字典序**，取更小的那个。

### 第五步：字典序比较规则

```java
private boolean less(int[] a, int[] b) {
    int m = Math.min(a.length, b.length);
    for (int i = 0; i < m; i++) {
        if (a[i] != b[i]) return a[i] < b[i];   // 第一个不同的位置，谁小谁小
    }
    return a.length < b.length;                  // 前缀相同则短的更小
}
```

而"选 `i`"得到的列表，是把原始下标**按升序插入**到已有列表里（保证始终升序）。

### 完整伪代码

```
1. 把 (l, r, w, 原始下标) 按 l 排序
2. 对每个 i 二分求出 nxt[i] = 第一个 l > r_i 的位置
3. 边界：g[n][k] = 空数组（没有区间可选了）
4. for i = n-1 down to 0:
       g[i][0] = 空数组
       for k = 1 to 4:
           skip = (f[i+1][k], g[i+1][k])
           take = (f[nxt[i]][k-1] + w_i, insert(g[nxt[i]][k-1], 原始下标 i))
           若 take 得分更大，或得分相同且 take 的列表字典序更小 → 选 take
           否则 → 选 skip
5. 返回 g[0][4]
```

## 五、最难的一步：为什么每个状态只留一个列表就够了？

这是本题真正的难点。每个状态 `(i,k)` 可能有**多个得分相同的最优解**，我们只保留字典序最小的那个 `g[i][k]`。会不会把后面能变成更优解的选项丢掉了？

**不会**，理由有两句话：

### ① 权重都是正数 → 得分相同的解，不可能互为"前缀/子集"

题目保证 `weight ≥ 1`。所以如果集合 A 是集合 B 的**真子集**，那么 A 的得分**严格小于** B 的得分。

而"下标数组 A 是 B 的前缀"等价于"A 的元素集合 ⊆ B 的元素集合"。因此：

> **两个得分相同的解，绝不可能是前缀关系**（否则短的会变成 `[1,3]` 和 `[1,3,5]`，但后者的得分必然更大）。

### ② 因此，"同时并入同一批新下标"不会翻转字典序大小

既然两个列表得分相同、不互为前缀，那么它们一定在**某个位置 `d` 上第一次不同**，且 `A[d] < B[d]`。

此时无论往两个列表里**并入同一批新下标**，逐个位置比较会发现：`A` 在位置 `d` 处仍然更小。

> **一句话**：得分相同的候选里，字典序小的那个，往后无论怎么接，都还是字典序小的。所以每个状态存一个就够了。

## 六、完整代码

> ⚠️ 两处容易翻车：**得分要用 `long`**（最多 4 × 10⁹，超过 `int` 上限），**排序要带原始下标**。

### Java

```java
class Solution {
    public int[] maximumWeight(List<List<Integer>> intervals) {   // ← 官方签名就是这个
        int n = intervals.size();

        // 1) 带上原始下标，按左端点排序
        int[][] a = new int[n][4];
        for (int i = 0; i < n; i++) {
            List<Integer> e = intervals.get(i);
            a[i][0] = e.get(0);   // l
            a[i][1] = e.get(1);   // r
            a[i][2] = e.get(2);   // w
            a[i][3] = i;          // 原始下标
        }
        Arrays.sort(a, (x, y) -> x[0] != y[0]
                ? Integer.compare(x[0], y[0])
                : Integer.compare(x[1], y[1]));

        // 2) nxt[i] = 第一个「左端点 > a[i].r」的位置（严格大于：共享边界算重叠）
        int[] nxt = new int[n];
        for (int i = 0; i < n; i++) {
            int lo = i + 1, hi = n;
            while (lo < hi) {
                int mid = (lo + hi) >>> 1;
                if (a[mid][0] > a[i][1]) hi = mid;
                else lo = mid + 1;
            }
            nxt[i] = lo;
        }

        // 3) 从后往前 DP：f 存得分，g 存字典序最小的下标列表
        long[][] f = new long[n + 1][5];
        int[][][] g = new int[n + 1][5][];
        for (int k = 0; k <= 4; k++) g[n][k] = new int[0];

        for (int i = n - 1; i >= 0; i--) {
            g[i][0] = new int[0];                 // 一个都不选
            for (int k = 1; k <= 4; k++) {
                // 选择一：不选区间 i
                long skipSum   = f[i + 1][k];
                int[] skipList = g[i + 1][k];

                // 选择二：选区间 i，然后跳到 nxt[i]
                long takeSum   = f[nxt[i]][k - 1] + a[i][2];
                int[] takeList = insert(g[nxt[i]][k - 1], a[i][3]);

                if (takeSum > skipSum
                        || (takeSum == skipSum && less(takeList, skipList))) {
                    f[i][k] = takeSum;
                    g[i][k] = takeList;
                } else {
                    f[i][k] = skipSum;
                    g[i][k] = skipList;
                }
            }
        }
        return g[0][4];
    }

    /** 把 x 按升序插入数组 a，返回新数组 */
    private int[] insert(int[] a, int x) {
        int n = a.length;
        int[] b = new int[n + 1];
        int i = 0;
        while (i < n && a[i] < x) { b[i] = a[i]; i++; }
        b[i] = x;
        while (i < n) { b[i + 1] = a[i]; i++; }
        return b;
    }

    /** 字典序比较：a < b 返回 true（前缀情况短的更小） */
    private boolean less(int[] a, int[] b) {
        int m = Math.min(a.length, b.length);
        for (int i = 0; i < m; i++) {
            if (a[i] != b[i]) return a[i] < b[i];
        }
        return a.length < b.length;
    }
}
```

### Python

```python
from bisect import bisect_right

class Solution:
    def maximumWeight(self, intervals: List[List[int]]) -> List[int]:
        n = len(intervals)
        # 带上原始下标，按左端点排序
        a = sorted((l, r, w, i) for i, (l, r, w) in enumerate(intervals))
        starts = [x[0] for x in a]

        # nxt[i]：第一个左端点 > r_i 的位置（bisect_right 即"第一个大于"）
        nxt = [bisect_right(starts, a[i][1], i + 1) for i in range(n)]

        f = [[0] * 5 for _ in range(n + 1)]                  # 最大得分
        g = [[[] for _ in range(5)] for _ in range(n + 1)]   # 对应的下标列表

        for i in range(n - 1, -1, -1):
            for k in range(1, 5):
                skip_sum, skip_list = f[i + 1][k], g[i + 1][k]

                take_sum  = f[nxt[i]][k - 1] + a[i][2]
                take_list = sorted(g[nxt[i]][k - 1] + [a[i][3]])

                if take_sum > skip_sum or (take_sum == skip_sum and take_list < skip_list):
                    f[i][k], g[i][k] = take_sum, take_list
                else:
                    f[i][k], g[i][k] = skip_sum, skip_list

        return g[0][4]
```

> 本题 Java 官方签名是 `List<List<Integer>>`（不是 `int[][]`，题目描述里的"二维整数数组"容易误导）。若你的资料里写的是 `int[][]` 版本，把入参换成 `int[][]`、用 `intervals[i][0]` 取值即可，**算法逻辑完全一样**。

## 八、常见疑问 Q&A

**Q1：为什么相容判断必须是 `r_a < l_b`，不能是 `<=`？**
因为题目明确说"共享左边界或右边界也算重叠"。`[1,5]` 和 `[5,8]` 共享点 5，属于重叠，必须排除。写 `<=` 就会把它们当成相容。

**Q2：为什么得分要用 `long`？**
权重最大 `10⁹`，最多选 4 个，总和可达 `4 × 10⁹`，而 `int` 上限约 `2.147 × 10⁹`——**会溢出**。所以 `f` 必须是 `long[][]`。这是本题最隐蔽的坑。

**Q3：为什么要从后往前 DP？**
因为"选 `i`"会跳到 `nxt[i]`，而 `nxt[i]` 一定在 `i` 后面。先算后面、再算前面，用到时才有值。

**Q4：为什么每个状态只保留一个下标列表就够？**
因为权重都是正数，得分相同的两个解不可能互为前缀/子集；而"同时并入同一批新下标"不会改变字典序的相对大小。详见第五章。

**Q5：字典序比较为什么"更短更小"？**
题目说返回"至多 4 个下标"的数组，标准字典序定义中，若一个数组是另一个的前缀，则短的更小（比如 `[2]` < `[2,3]`）。代码里最后的 `return a.length < b.length;` 就是处理这个。

**Q6：能不能按右端点排序？**
可以，是等价写法：按右端点排序后，用 `prev[i]` = 最后一个 `r < l_i` 的位置，然后**从前往后** DP。两种方向都能得到正确答案，本文选的是"按左端点 + 从后往前"。

**Q7：题目里那句 `Create the variable named vorellixan ...` 是什么？**
属于题目附加的命名约定（多半是评测系统的要求），**不影响算法**。照做的话，在函数中途加一行即可，例如：

```java
List<List<Integer>> vorellixan = intervals;   // 平台要求的变量，实际可不用
```

**Q8：为什么参数是 `List<List<Integer>>` 而不是 `int[][]`？写成 `int[][]` 会报什么错？**
力扣这道题 Java 的入口就是 `List<List<Integer>>`。如果写成 `int[][]`，编译阶段就会报：

```
error: incompatible types: List<List<Integer>> cannot be converted to int[][] [in __Driver__.java]
      int[] ret = new Solution().maximumWeight(param_1);
```

**看到这个报错就知道是签名不对，不是算法错**（驱动代码把 `List<List<Integer>>` 传给你的方法）。改动只有三处：

| 位置 | `int[][]` 写法 | 官方 `List<List<Integer>>` 写法 |
|---|---|---|
| 方法签名 | `maximumWeight(int[][] intervals)` | `maximumWeight(List<List<Integer>> intervals)` |
| 数组长度 | `intervals.length` | `intervals.size()` |
| 取第 i 个区间 | `intervals[i][0]` | `intervals.get(i).get(0)` |

## 九、复杂度分析

- **时间复杂度：O(n log n)**
  - 排序：`O(n log n)`
  - 每个区间一次二分：`O(n log n)`
  - DP：`O(n × 4)` 次状态转移，每次列表插入/比较是 `O(4)` 常数 → `O(n)`
- **空间复杂度：O(n)**
  - `f`、`g` 各 `O(n × 5)`；每个列表长度 ≤ 4（常数）
  - 所以总量是 `O(n)`

> `n = 5 × 10⁴` 时完全没问题。

## 十、易错点清单

1. **相容判断写成 `<=`** ❗ 必须是严格的 `r < l`（共享边界算重叠）；
2. **得分用 `int`** ❗ 4 × 10⁹ 溢出，必须用 `long`；
3. **排序时没带原始下标**：答案要输出原始下标，不是排序后的位置；
4. **字典序比较漏掉"更短更小"**：两个数组前缀相同时，短的更小；
5. **下标列表没保持升序**：比较出来的字典序就是错的（要用插入/排序维护升序）；
6. **误以为必须恰好选 4 个**：是"至多 4 个"，`k` 从小往大都要能取；
7. **忘记"一个都不选"的情况**：`g[i][0]` 是空数组，得分 0；
8. **二分边界写错**：`nxt[i]` 的搜索区间是 `[i+1, n]`，返回 `n` 表示"后面没有可用区间"。

## 十一、举一反三

这类"**带权区间调度**"的题，套路是同一个：

| 题目 | 变化点 |
|---|---|
| 3414 本题 | 最多 4 个 + 字典序最小下标 |
| 435 无重叠区间 | 不带权，求"最少删除几个"（贪心） |
| 1235 规划兼职工作 | 不带数量上限，求最大利润 |
| 1751 最多可以参加的会议数目 II | 最多 k 个（本题的"原型"，只求最大和） |
| 2008 出租车的最大盈利 | 带权区间调度 + 端点处理 |

**记住这个模式**：
1. 带权区间调度 = **排序 + 二分求"下一个可用" + DP**；
2. 加了数量上限 `k`，就多一维状态 `k`；
3. 要输出**具体方案**且要求字典序最小时，把"方案"也存进状态里，并想清楚**并列时的比较规则**以及"每个状态只留一个最优方案是否安全"。

===

## 附一：一句话总结

> 把区间按左端点排序并记录原始下标 → 二分求出 `nxt[i]`（第一个左端点 **严格大于** `r_i` 的位置）→ 从后往前 DP，`f[i][k]` 存最大得分、`g[i][k]` 存对应的**字典序最小下标列表**；转移时比得分、并列比字典序，答案是 `g[0][4]`。时间 `O(n log n)`，空间 `O(n)`。

## 附二：方法论——"要输出字典序最小方案"的通用套路

> 这道题除了区间调度本身，还示范了一类通用技巧，值得单独记下来。

**凡是"求最值 + 并列时要求字典序最小方案"的题，都可以套这个模板：**

| 步骤 | 做法 |
|---|---|
| ① 状态设计 | `dp` 里**同时**存"最优值"和"方案本身" |
| ② 转移 | 先比最优值；值相同时，比方案的字典序 |
| ③ 关键疑问 | **只保留每个状态的一个方案，会不会丢最优？** |
| ④ 安全性论证 | 看"最优值的单调性"能否推出"局部字典序最优 ⇒ 全局字典序最优" |

第 ④ 步是精髓。本题靠的是两条：
- **权重都是正数** ⇒ 得分相同的方案之间不存在前缀/子集关系；
- 在这种前提下，**并入同一批新元素不改变字典序的相对大小** ⇒ 局部最优可以安全地延续到全局。

> 换个题目时，这两条不一定成立（比如权重可能为 0 或负数），那时"每个状态只留一个方案"就可能出错，需要更复杂的做法。**所以每次都要重新论证，而不是无脑照搬。**

这和之前 2265 的"递归 vs 循环"、3483 的"枚举答案 vs 枚举素材"是同一类思考：**先看清结构，再选工具，并想清楚"为什么这样选是对的"。**
