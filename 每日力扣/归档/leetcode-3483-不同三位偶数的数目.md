# 3483. 不同三位偶数的数目

> 题目：
> 
> 给你一个数字数组 `digits`，你需要从中选择三个数字组成一个三位偶数，你的任务是求出 **不同** 三位偶数的数量。
>
> 注意：每个数字在三位偶数中都只能使用 **一次**，并且 **不能** 有前导零。
>
> 示例 1：`digits = [1,2,3,4]` → 输出 `12`
> 示例 2：`digits = [0,2,2]` → 输出 `2`（只有 202 和 220）
> 示例 3：`digits = [6,6,6]` → 输出 `1`（只有 666）
> 示例 4：`digits = [1,3,5]` → 输出 `0`
>
> 提示：`3 <= digits.length <= 10`；`0 <= digits[i] <= 9`

> 📖 **阅读顺序说明**：这份文档按"从零开始"来写——
> 第一章先拆解题目的三个约束和一个大陷阱；
> 第二章用人脑手算几个例子，找出规律；
> 第三章讲有哪两条枚举路线、怎么选；
> 第四、五章分别把两种思路拆成步骤；
> 第六章是完整代码；第七章拿示例逐行走查；
> 第八章集中回答初学者最容易卡住的疑问。
>
> 如果你时间紧，可以直接跳到 **第四章** 看推荐思路。

## 一、先把题目读懂（三个约束 + 一个大陷阱）

题目看着简单，但"从数组里挑三个数字拼三位数"这件事，藏着三个约束和一个最容易踩的坑。

### 1.1 约束一：必须是三位数 → 百位不能是 0

三位数的首位（百位）不能是 `0`，否则就成了两位数。比如 `[0,2,2]` 里不能拼出 `022`。

### 1.2 约束二：必须是偶数 → 个位只能是 0、2、4、6、8

一个数是偶数，只看它的**最后一位**。所以个位必须是 `{0, 2, 4, 6, 8}` 之一。示例 4 的 `[1,3,5]` 里全是奇数，拼不出任何偶数，答案是 0。

### 1.3 约束三：每个数字的"份数"有限制

> 题目说"每个数字只能使用 **一次**"，准确的理解是：**每一份只能用一次**。

看示例 3：`digits = [6,6,6]` 里 6 有**三份**，所以可以拼出 `666`（用了三份 6）。
而示例 1 的 `[1,2,3,4]` 里 2 只有**一份**，所以 `222` 拼不出来。

> 所以正确的做法是**统计每个数字有几份**，用的时候扣减——而不是简单地判断"这个数字在不在数组里"。

### 1.4 ⚠️ 最大的陷阱：千万不能给 digits 去重

很多人的第一反应是"先把数组去重，这样就不会重复计算了"——**大错**：

```
digits = [6,6,6]
去重后 → [6]      ← 只剩一份 6，连 666 都拼不出来，答案会变成 0
正确答案 → 1（666）
```

**要去重的是最终得到的那个三位数，不是输入数组。**

### 1.5 题目要求（大白话版）

> 用数组里的数字（每个数字有几份就只能用几次），拼出所有**合法**的三位数（百位非 0、个位是偶数），然后数一数 **一共有多少个不同的数**。注意是数"不同的数"，同一个数用不同顺序拼出来只算一次。

## 二、人脑会怎么算这道题？

### 2.1 先看最简单的例子：`digits = [6,6,6]`

手上的数字：三个 6。

- 百位放 6，十位放 6，个位放 6 → 得到 `666`
- 个位是 6，是偶数 ✅；百位是 6，非 0 ✅
- 还有别的拼法吗？没有了（数字都一样，怎么换来换去还是 666）

**答案 = 1**。注意：虽然"选哪三份 6"有好几种选法，但**得到的数只有一个**——题目问的是"不同的数"，不是"不同的选法"。

### 2.2 手算示例 2：`digits = [0,2,2]`

手上的数字：一个 `0`，两个 `2`。

我们按"百位 → 十位 → 个位"的顺序试着拼：

| 尝试 | 百位 | 十位 | 个位 | 是否合法 | 说明 |
|---|---|---|---|---|---|
| `022` | 0 | 2 | 2 | ❌ | 百位是 0，不是三位数 |
| `202` | 2 | 0 | 2 | ✅ | 用了两个 2 + 一个 0，够用 |
| `220` | 2 | 2 | 0 | ✅ | 用了两个 2 + 一个 0，够用 |
| `222` | 2 | 2 | 2 | ❌ | 需要三个 2，但手上只有两个 |

**答案 = 2**（202 和 220）✓

### 2.3 手算示例 1：`digits = [1,2,3,4]`

四个数字各一份。按**个位是几**来分类枚举最清晰：

**个位是 2**（百位、十位从 `{1,3,4}` 里选两个排列）：
`132、312、142、412、342、432` → 6 个

**个位是 4**（百位、十位从 `{1,2,3}` 里选两个排列）：
`124、214、134、314、234、324` → 6 个

合计 `6 + 6 = 12` 个 ✓ 与题目给的 12 个完全一致。

### 2.4 从手算里发现的两条路

手算时你其实做了两件不同的事：

1. **2.2 节**：我是在"试着拼出一个具体的数"（202、220……），然后检查合不合法；
2. **2.3 节**：我也是在"想具体的数"，但用了个位分类来避免遗漏。

这说明：**这道题的核心动作就是"枚举三位数，检查能不能拼出来"**。那么问题来了——枚举什么？有两种选法，见下一章。

## 三、从人脑到代码：两条枚举路线

### 3.1 两条路线长什么样

| | 路线 A：枚举**答案** | 路线 B：枚举**素材** |
|---|---|---|
| 枚举对象 | 所有三位偶数（100 ~ 999） | 数组里的下标组合 (i, j, k) |
| 对每个候选做什么 | 检查"它的三个数字我够不够用" | 检查合法性后拼成数字，丢进 Set |
| 去重方式 | **天然不重复**（每个数只检查一次） | 需要 `HashSet` 帮忙去重 |
| 前导零 | **天然排除**（从 100 开始） | 需要**显式判断**百位非 0 |
| 循环次数 | 900 次 | n³ ≤ 1000 次 |
| 推荐度 | ⭐⭐⭐⭐⭐（省心） | ⭐⭐⭐（最好想） |

### 3.2 为什么说"枚举答案"更省心

因为**所有麻烦都被枚举范围本身解决掉了**：

- 我们从 100 开始枚举 → 百位 `num / 100` 最小是 1 → **不可能出现前导零**，不用写判断；
- 每个三位数只会被"走过"一次 → **不可能重复计数**，不用 Set；
- 只需要回答一个问题："这个数的三个数字，我手上的份数够不够？"

> 一句话：**与其"从素材拼出答案再去重"，不如"直接列举答案，看它拼不拼得出来"。**

## 四、思路 A（推荐）：枚举 100 ~ 999 的所有偶数

### 4.1 分三步走

**第一步：统计手上每个数字有几份。**

```java
int[] have = new int[10];
for (int d : digits) have[d]++;
```

比如 `[0,2,2]` → `have[0]=1, have[2]=2`，其余为 0。

**第二步：枚举 100 ~ 999 的每一个偶数。**

```java
for (int num = 100; num <= 999; num++) {
    if (num % 2 != 0) continue;   // 奇数直接跳过
```

> Python 里可以更直接：`for num in range(100, 1000, 2)`，步长 2 直接只走偶数。

**第三步：拆出三个数字，检查份数够不够。**

```java
int a = num / 100;          // 百位
int b = num / 10 % 10;      // 十位
int c = num % 10;           // 个位
```

### 4.2 关键动作：判断"份数够不够用"

思路是：把候选数的三个数字也统计一份 `need[]`，然后逐个对比 `need[d] <= have[d]`。

以 `have = [1,0,2,0,...]`（即 `[0,2,2]`）为例：

| 候选数 | need[] | 够不够？ | 原因 |
|---|---|---|---|
| 200 | need[2]=1, need[0]=2 | ❌ | 需要两个 0，但只有 1 个 |
| 202 | need[2]=2, need[0]=1 | ✅ | 两个 2、一个 0，正好 |
| 220 | need[2]=2, need[0]=1 | ✅ | 同上 |
| 222 | need[2]=3 | ❌ | 需要三个 2，但只有 2 个 |

> 这就是"多重集包含"判断：候选数的数字构成，必须是手上数字构成的"子多重集"。

### 4.3 完整伪代码

```
have[0..9] = digits 里每个数字的份数
ans = 0

for num = 100 to 999:
    如果 num 是奇数: 跳过

    need[0..9] = 0
    need[num的百位] += 1
    need[num的十位] += 1
    need[num的个位] += 1

    如果 对所有 d 都有 need[d] <= have[d]:
        ans = ans + 1

返回 ans
```

## 五、思路 B：三重循环枚举下标 + HashSet

### 5.1 分三步走

**第一步：枚举三个**互不相同**的下标**（`i` 百位、`j` 十位、`k` 个位）。

```java
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        for (int k = 0; k < n; k++)
            if (i == j || j == k || i == k) continue;   // 同一个位置不能重复用
```

> 为什么要判断下标互不相同？因为每个数字只能使用一次，而**同一个下标用了两次就等于把那份数字用了两次**。

**第二步：检查三个约束。**

```java
if (digits[i] == 0) continue;        // 百位不能是 0（前导零）
if (digits[k] % 2 != 0) continue;    // 个位必须是偶数
```

**第三步：拼成数字，丢进 Set 去重。**

```java
seen.add(digits[i] * 100 + digits[j] * 10 + digits[k]);
```

### 5.2 为什么必须要 Set

因为数组里**可能有重复数字**，不同的下标组合会拼出**同一个数**：

```
digits = [0,2,2]（下标 0→0，1→2，2→2）
(i,j,k) = (1,0,2) → 202
(i,j,k) = (2,0,1) → 202   ← 又是 202，只是用了"另一个 2"
```

如果不用 Set，`202` 会被数两次。Set 自动帮我们只保留一份。

> 也正因为要处理这种情况，思路 B 必须"先拼出来再去重"；而思路 A 天然没有这个问题。

## 六、完整代码

### 思路 A（推荐）

```java
class Solution {
    public int totalNumbers(int[] digits) {
        int[] have = new int[10];
        for (int d : digits) have[d]++;          // 每个数字有几份

        int ans = 0;
        for (int num = 100; num <= 999; num++) {
            if (num % 2 != 0) continue;           // 必须是偶数

            int a = num / 100;                    // 百位（≥1，天然无前导零）
            int b = num / 10 % 10;                // 十位
            int c = num % 10;                     // 个位

            int[] need = new int[10];
            need[a]++; need[b]++; need[c]++;

            boolean ok = true;
            for (int d = 0; d < 10; d++) {
                if (need[d] > have[d]) { ok = false; break; }
            }
            if (ok) ans++;
        }
        return ans;
    }
}
```

```python
class Solution:
    def totalNumbers(self, digits: List[int]) -> int:
        have = [0] * 10
        for d in digits:
            have[d] += 1

        ans = 0
        for num in range(100, 1000, 2):        # 步长 2：只遍历偶数
            need = [0] * 10
            for ch in str(num):                # 拆出三个数字
                need[int(ch)] += 1
            if all(need[d] <= have[d] for d in range(10)):
                ans += 1
        return ans
```

### 思路 B（三重循环 + Set）

```java
class Solution {
    public int totalNumbers(int[] digits) {
        Set<Integer> seen = new HashSet<>();
        int n = digits.length;

        for (int i = 0; i < n; i++) {
            if (digits[i] == 0) continue;              // 百位不能是 0
            for (int j = 0; j < n; j++) {
                if (j == i) continue;
                for (int k = 0; k < n; k++) {
                    if (k == i || k == j) continue;     // 三个位置互不相同
                    if (digits[k] % 2 != 0) continue;   // 个位必须是偶数
                    seen.add(digits[i] * 100 + digits[j] * 10 + digits[k]);
                }
            }
        }
        return seen.size();
    }
}
```

```python
class Solution:
    def totalNumbers(self, digits: List[int]) -> int:
        seen = set()
        n = len(digits)

        for i in range(n):
            if digits[i] == 0: continue
            for j in range(n):
                if j == i: continue
                for k in range(n):
                    if k == i or k == j: continue
                    if digits[k] % 2 != 0: continue
                    seen.add(digits[i] * 100 + digits[j] * 10 + digits[k])

        return len(seen)
```

## 七、拿示例走一遍代码

### 7.1 示例 2：`digits = [0,2,2]`，用思路 B 逐行走查

下标对应：`0 → 0`，`1 → 2`，`2 → 2`。

| 百位 i | 十位 j | 个位 k | 检查 | 拼出的数 | Set 内容 |
|---|---|---|---|---|---|
| 0(0) | — | — | 百位是 0 → 跳过 | — | {} |
| 1(2) | 0(0) | 2(2) | 全通过 | `202` | {202} |
| 1(2) | 2(2) | 0(0) | 全通过 | `220` | {202, 220} |
| 1(2) | 2(2) | 2(2) | k==j → 跳过 | — | — |
| 2(2) | 0(0) | 1(2) | 全通过 | `202`（重复） | {202, 220} |
| 2(2) | 1(2) | 0(0) | 全通过 | `220`（重复） | {202, 220} |
| 其余 | | | 大多被下标/偶数检查挡掉 | | |

最终 `seen.size() = 2` ✅ 与答案一致。

### 7.2 用思路 A 验证示例 1：`digits = [1,2,3,4]`

`have[1]=have[2]=have[3]=have[4]=1`，其余为 0。

遍历 100~999 的偶数，只有"三个数字互不相同且都在 {1,2,3,4} 中"的才通过：

- 个位 = 2 的：`132、312、142、412、342、432` → 6 个
- 个位 = 4 的：`124、214、134、314、234、324` → 6 个

合计 12 ✅

> 注意 `222`：需要三个 2，但 `have[2] = 1`，在份数检查时被判为 ❌，正确地排除了。

## 八、常见疑问 Q&A

**Q1：为什么不能先把 `digits` 去重？**
因为"重复的数字"是**可用的份数**。`[6,6,6]` 去重后只剩一份 6，就拼不出 666，答案会从 1 变成 0。要去重的是**最终得到的数**，不是输入的数字。

**Q2：前导零怎么处理？**
两条路线的处理方式不同：
- 思路 A：从 100 开始枚举，百位最小是 1，**天然不会出现前导零**；
- 思路 B：必须显式写 `if (digits[i] == 0) continue;`，因为 i 可能指向数字 0。

**Q3：为什么思路 B 一定要用 Set？用 List 行不行？**
不行（会算重）。因为数组里可能有重复数字，不同的下标组合能拼出同一个数（如 `[0,2,2]` 里 `(1,0,2)` 和 `(2,0,1)` 都是 202）。题目问的是"不同的数"，必须去重。

**Q4：思路 A 为什么不需要去重？**
因为它是**枚举答案**：每个三位数（比如 202）在整个循环里只会被检查一次，通过了就 `ans++`，天然不存在重复计数。

**Q5：`[6,6,6]` 为什么答案是 1，不是 6？**
因为"选哪几份 6"虽然有不同的选法，但**拼出来的数都是 666**。题目问的是不同**三位偶数**的个数，不是不同**选法**的个数。

**Q6：为什么思路 B 里判断偶数是 `digits[k] % 2`，而不是别的？**
因为 `k` 是**个位**的下标。一个整数是否为偶数只取决于个位数字，所以只要个位数字是偶数，整个三位数就是偶数。

**Q7：如果数组里有 0，它能放在十位或个位吗？**
可以！只有**百位**不能是 0。比如 `[0,2,2]` 里的 `202`、`220` 都用到了 0，分别放在十位和个位，都是合法的。

## 九、复杂度分析

| 思路 | 时间复杂度 | 空间复杂度 | 说明 |
|---|---|---|---|
| A 枚举答案 | O(900 × 10) ≈ O(1) | O(1) | 900 个偶数，每个比较 10 个数字 |
| B 枚举下标 | O(n³)，n ≤ 10 → 最多 1000 次 | O(答案数) ≤ 900 | 三重循环 + Set |

- 两条路线都远远快于时限，**随便写都能过**；
- 由于 `digits.length ≤ 10`，思路 B 的 n³ 最多也就 1000 次，完全不用担心。

## 十、易错点清单

1. **把 `digits` 去重了** ❌ —— 这是最致命的错，`[6,6,6]` 会输出 0 而不是 1；
2. **忘了前导零**：思路 B 必须显式判断百位非 0；思路 A 靠"从 100 开始"规避；
3. **忘了偶数约束**：个位必须是 0/2/4/6/8，否则 `[1,3,5]` 会错误地输出非 0 的结果；
4. **三重循环忘了 `(i,j,k)` 互不相同**：同一个下标用两次，等于把一份数字用了两次（比如 `[1,2,3,4]` 会错算出 111、222 之类）；
5. **思路 B 没用 Set**：会把 202 之类的重复数算多次；
6. **误以为"有 0 就一定非法"**：0 只在百位时非法，放在十位、个位完全合法。

## 十一、举一反三

这类"**从给定素材里凑出满足条件的数/组合，并去重**"的题，套路非常固定：

| 题目类型 | 核心动作 |
|---|---|
| 3483 本题 | 枚举答案 → 检查素材够不够 |
| 全排列 / 组合总和 | 递归枚举 + 用 Set 或排序去重 |
| 两数之和 / 三数之和 | 枚举 + 哈希表或双指针去重 |
| 下一个更大排列 | 枚举 + 字典序规则 |

**记住这个模式**：
- 如果**答案的取值范围很小**（比如本题只有 900 个三位数），那就**枚举答案**，再回头检查"素材够不够"——这样天然去重，最省心；
- 如果**答案的取值范围很大**，才需要**枚举素材 + 显式去重**。

## 附一：一句话总结

> 统计 `digits` 里每个数字有几份，然后**枚举 100 ~ 999 的所有偶数**，把它拆成三个数字、检查手上的份数够不够——天然去重、天然排除前导零，是最省心的写法。全程 O(1)（900 次检查）。

## 附二：方法论——"枚举答案"还是"枚举素材"？

> 这道题藏着一个很通用的思路，值得单独记下来。

做枚举类题目时，**枚举谁**是一个关键选择：

| | 枚举素材（输入） | 枚举答案（输出） |
|---|---|---|
| 做法 | 从输入里挑组合，拼出结果 | 列举所有可能的结果，检查能不能由输入拼出 |
| 适合场景 | 答案空间大、素材少 | **答案空间小**、素材可数 |
| 去重 | 通常需要 Set | 天然不重复 |
| 本题 | 三重循环下标 (i,j,k) | 100~999 的偶数 |

**怎么选？先估计一下"答案空间"有多大：**

- 本题的答案空间只有 900 个三位数 → **果断枚举答案**，几乎白送"去重"和"合法性剪枝"；
- 如果题目是"从 1000 个数里选 3 个"（答案空间巨大）→ 就老老实实枚举素材 + 去重。

> 这和之前 2265 题"为什么用递归"的思考是同一个道理：**先看清问题的结构，再选工具**——结构决定了哪种写法更自然、更不容易错。
