# 940. 不同的子序列 II（Distinct Subsequences II）

> 题目：
> 
> 给定一个字符串 `s`，计算 `s` 的 **不同非空子序列** 的个数。因为结果可能很大，所以返回答案需要对 `10^9 + 7` 取余。
>
> 字符串的 **子序列** 是经由原字符串删除一些（也可能不删除）字符但不改变剩余字符相对位置的一个新字符串。

> 📖 参考阅读：`leetcode-115-不同的子序列.md`（数特定模式 `t` 出现次数）；本题是数**所有**不同子序列，多了一个难点——**去重**。

===

## 一、题面解读

和 115 题一样是「子序列计数」，但问法不同：

- **115**：数 `t` 在 `s` 的子序列里出现了几次（指定目标）；
- **940**：数 `s` 的**所有不同非空子序列**一共有几个（不指定目标）。

难点全在"**不同**"两个字上。示例 2 最能说明问题：

`s = "aba"`，若允许重复计数，非空子序列 = `2^3 - 1 = 7` 个；但因为 `"a"` 可以由第 1 个 `a` 单独选出、也可以由第 3 个 `a` 单独选出，**同一个子序列被算重了**，正确答案是 **6**。

> 本质：子序列是"选位置"，不同选法可能得到**同一个字符串**，要去重到"不同的字符串"为止。

## 二、思路：按"以什么字符结尾"分组去重

### 2.1 核心洞察

**重复只会发生在"以同一个字符结尾"的子序列之间。**

为什么？两个不同的子序列如果相等，它们的**最后一个字符必然相同**。所以想避免重复，就按 **末尾字符分组** 统计：

```
ends[c] = 当前已经形成的、以字符 c 结尾的 不同子序列个数
```

### 2.2 递推：处理一个新字符 ch

把所有已有的子序列（**含空串**）后面都接上 `ch`，会得到一批**都以 ch 结尾**的新候选——数量正好等于当前子序列总数 `total`（含空串）。

这些新候选大部分是新面孔，但有一批是"旧相识"：

> 若 `x + ch` 这个串**以前就存在**，它必然以 `ch` 结尾；而旧的以 `ch` 结尾的子序列去掉末尾的 `ch`，又能唯一还原出 `x`。
> 所以 **新候选里重复的个数 = 旧的 `ends[ch]`**，一个不多一个不少。

于是：

```
新增真正不同的个数 = total（含空串） - 旧的 ends[ch]
新的 total       = 旧 total + 新增 = 2 × 旧 total - 旧的 ends[ch]
新的 ends[ch]   = 旧 total          （接上 ch 后以 ch 结尾的候选总数）
```

> 大白话版本：每个已有子序列都有"不接 ch / 接 ch"两种选择 → 总数先**翻倍**；其中以 ch 结尾的"接 ch"结果会和过去的以 ch 结尾的子序列**撞车**，把重复的 `ends[ch]` 减掉。

### 2.3 边界与答案

- 一开始只有**空串** 1 个 → `total = 1`（注意 total 全程**含空串**，否则单个字符子序列 `"a"` 都产生不出来）；
- `ends` 初始全 0；
- 最终答案去掉空串：`(total - 1) % MOD`。

## 三、手推验证示例

### 3.1 示例 2：`s = "aba"`（逐步演算）

`total` 含空串，`ends` 记"以某字母结尾"的子序列数：

| 步骤 | 读到 | total（含空） | 计算过程 | ends 变化 | 含义 |
|---|---|---|---|---|---|
| 初始 | - | 1 | - | 全 0 | 只有空串 |
| 1 | `a` | 2 | `2×1 − ends[a](0) = 2` | ends[a]=1 | 新增 `"a"` |
| 2 | `b` | 4 | `2×2 − ends[b](0) = 4` | ends[b]=2 | 新增 `"b"、"ab"` |
| 3 | `a` | 7 | `2×4 − ends[a](1) = 7` | ends[a]=4 | 新增 3 个，`"a"` 重复被减 |

答案 `total - 1 = 6` ✓

第 3 步为什么只新增 3 个？现有子序列（含空）`{"", "a", "b", "ab"}` 后面都接 `'a'` → `{"a", "aa", "ba", "aba"}`，其中 `"a"` 早就有了，**重复的恰好就是旧的 `ends['a'] = 1` 个**，减掉即可。

### 3.2 示例 1：`s = "abc"`

`total：1 → 2 → 4 → 8`（每个字符都从没出现过，ends 全 0，从不用减），答案 `8 - 1 = 7` ✓

### 3.3 示例 3：`s = "aaa"`

`total：1 → 2 → 3 → 4`（每次都减掉刚更新的 ends['a']），答案 `4 - 1 = 3` ✓
（三个不同子序列是 `"a"、"aa"、"aaa"`，和位置无关，只和取几个有关）

## 四、代码实现

### Python

```python
class Solution:
    def distinctSubseqII(self, s: str) -> int:
        MOD = 10**9 + 7
        ends = [0] * 26      # ends[c]：当前以字符 c 结尾的不同子序列个数
        total = 1            # total：含空串在内的子序列总数，初始只有空串
        for ch in s:
            i = ord(ch) - ord('a')
            new_ends = total                     # 所有已有子序列(含空串)后接 ch → 都算以 ch 结尾
            total = (total * 2 - ends[i]) % MOD  # 去掉与旧以 ch 结尾的子序列重复的部分
            ends[i] = new_ends % MOD
        return (total - 1) % MOD                 # 去掉空串
```

### Java

```java
class Solution {
    public int distinctSubseqII(String s) {
        final int MOD = 1_000_000_007;
        int[] ends = new int[26];          // ends[c]：以字符 c 结尾的不同子序列个数
        long total = 1;                    // 含空串的总数，初始只有空串
        for (int i = 0; i < s.length(); i++) {
            int idx = s.charAt(i) - 'a';
            long newEnds = total;                       // 后接当前字符 → 以它结尾的候选
            total = (total * 2 - ends[idx]) % MOD;      // 减去重复部分
            if (total < 0) total += MOD;                // Java 取模可能是负数，修正
            ends[idx] = (int) newEnds;
        }
        return (int) ((total - 1 + MOD) % MOD);         // 去掉空串
    }
}
```

## 五、MOD 为什么是 10^9+7？取模到底在干嘛？

### 5.1 最直接的原因：题目规定的

题目原文写着「返回答案需要对 `10^9 + 7` 取余」。**答案必须按 `10^9 + 7` 取模**，否则和官方答案对不上。就像题目要求"输出保留两位小数"，你写三位就是错——这一层没有道理可讲，它是评分标准的一部分。

### 5.2 为什么算法题偏爱 `10^9+7` 这个数？

因为它是"各方面都刚刚好"的质数，几乎是竞赛圈的默认模数：

**① 它是一个质数（素数）**

`1_000_000_007` 是质数。质数的好处在于：很多题解到一半会用到**除法**（概率、组合数、期望等），而模运算下不能直接除，要算"模逆元"。质数保证 1 ~ p-1 的每个数都有逆元（用费马小定理 `a^(p-2)` 求）。
940 本身只用加减乘、用不到除法，但竞赛题喜欢统一用一个大质数，免得每道题换模数。

**② 大小约 10^9，运算"刚好不溢出"**

这是最实用的一条。编程里的整数有上限：

| 类型 | 上限 |
|---|---|
| int（32 位） | ≈ 2.147 × 10^9 |
| long（64 位） | ≈ 9.22 × 10^18 |

而模数 p ≈ 10^9，于是：
- 两个 < p 的数**相加** < 2 × 10^9 < int 上限 → **int 直接加不溢出**；
- 两个 < p 的数**相乘** ≈ 10^18 < long 上限 → **long 直接乘不溢出**。

如果模数取太大（比如接近 int 上限），两个数一加就溢出 int，每步都得用 long，麻烦又慢。

**③ 为什么非取模不可？因为真答案大到没边**

`s` 最长 2000，就算不去重，子序列都有 `2^2000 − 1` 个——这个数远超任何整数类型的容量。所以必须"边算边取模"。

### 5.3 为什么可以"边算边取模"？——模运算的分配律

有个数学事实让取模变得可行：**加减乘可以先取模再运算，结果不变**：

```
(a + b) % p == (a%p + b%p) % p
(a × b) % p == (a%p × b%p) % p
```

所以 DP 每步都 `% MOD`，最终结果和"先算完巨大答案再取模"完全一致——这就是代码里可以放心地每步取模的原因。

### 5.4 取模的两种"坑"写法

**坑 1：负数取模。** Java/Python 里负数对正数取模的行为不同：
- Python：`(-3) % 7 == 4`（结果永远非负，很友好）；
- Java：`(-3) % 7 == -3`（结果可能为负！）。

本代码 `total * 2 - ends[i]` 在减去重复部分时**可能算出负数**，所以 Java 里要加一行修正：

```java
total = (total * 2 - ends[idx]) % MOD;
if (total < 0) total += MOD;   // Java 取模可能是负数，修正到 [0, MOD)
```

**坑 2：乘法溢出。** Java 里 `total * 2` 若 `total` 是 `int`，最多约 2×10^9，还没溢出 int；但其它题目常见 `a * b`（两个都约 10^9）会爆 int，所以要么用 `long` 运算再取模，要么用 `(a % MOD) * (b % MOD) % MOD` 分段取模。本代码直接把 `total` 声明成 `long`，从源头避免乘 2 溢出。

> 一句话总结：`10^9+7` 首先是**题目指定**的模数；其次它作为"约 10 亿的质数"，既保证 int/long 运算不溢出，又为将来可能的除法留好退路。以后会一直见到它，记住"**大质数 + 运算不溢出的量级**"就够了。

## 六、复杂度与易错点

- **时间复杂度**：O(n)，一次遍历
- **空间复杂度**：O(26) = O(1)

易错点：

1. **`total` 必须包含空串**：否则第一个字符产生不了单字符子序列，答案整体少算；
2. **更新 `ends[i]` 要用更新前的 total**：先把 `newEnds = total` 存下来再改 total，顺序写反会连环错；
3. **取模防负数**：Java 里 `total * 2 - ends[i]` 可能为负，需要 `+ MOD` 修正（用 `long` 防乘 2 溢出）——原理详见第五章；
4. **最后记得减 1 去掉空串**。

## 七、和 115 题对比

| | 115 不同的子序列 | 940 不同的子序列 II |
|---|---|---|
| 数什么 | `t` 在 `s` 子序列中的出现次数 | `s` 所有不同非空子序列个数 |
| 难点 | 状态设计（`dp[i][j]` 二维） | **去重**（按末尾字符分组） |
| 复杂度 | O(m·n) | O(n) |
| 递推核心 | 字符相等 → 跳过 + 匹配 | 总数翻倍 − 旧的 `ends[ch]` |

共同点：都围绕 **"当前字符选 / 不选"** 做分支计数；区别是 940 多回答了一个问题——**"选出来的串会不会和别人撞车？"**，而撞车的唯一可能，就是末尾字符相同。

## 八、扩展

- 若不要求去重，答案退化为 `2^n − 1`（每个字符独立地选/不选，去掉全不选）——940 的所有"麻烦"都来自去重这一个点。
- 若题目改成**统计以每个不同子序列的长度分布**等变体，思路也可沿用"以末尾字符分组"避免重复的框架。
